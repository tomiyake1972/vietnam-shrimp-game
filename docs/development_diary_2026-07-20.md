## 1. 本日の到達点

本日は、ShrimpX V2の財務・投資領域を大きく前進させた。

Phase 8Aで構築した原価計算、運転資本、PL／BS／CFを正式に確定したうえで、Phase 8B-1では銀行信用、借入限度、金利、返済、緊急融資、資金制約、支払不能を接続した。さらにPhase 8B-2Aでは、設備投資を単発の支出ではなく、提案、承認、着工、複数四半期の建設、分割支払、中断、再開、完成、固定資産振替という時間を伴う案件として実装した。

これにより、ゲームの会社経営は次の段階へ進んだ。

1. 売上と利益を計算できる
2. 在庫と運転資本によって利益と現金がずれる
3. 業績と財務状態によって借入条件が変わる
4. 資金不足によって調達や事業活動が制約される
5. 設備投資には現金と建設期間が必要になる
6. 投資しても完成までは能力が増えない

つまり、財務諸表が単なる結果表示ではなく、次の意思決定を制約するゲームシステムとして機能し始めた。

## 3. 開発モデルの運用見直し

Phase 8AではFable 5「超高」に大規模実装を一括依頼した結果、約7時間以上を要し、週間Fable枠の約34%を使用した。会計設計から三表接続まで高品質に実装できた一方、最終stage後に長時間進まなくなり、Sonnet 5へcommit・push・完了報告を引き継いだ。

この経験から、今後は次の運用とした。

- Fable：複雑な横断設計、経済校正、難しい設計判断に限定
- Sonnet 5・高：通常の大規模実装、テスト、文書化
- Sonnet 5・標準：限定的な確認、テスト追加、merge作業
- 大きなPhaseは複数の小Phaseへ分割
- 長時間停止時は作業ツリーを保全してモデルを切り替える
- Fableへcommit、push、長い完了報告まで任せ続けない

Phase 8B以降は、この分割方針によって大幅に効率が改善した。

## 5. Phase 8B-1：資金繰り・借入・銀行信用

### 実装概要

Phase 8B-1では、会社ごとに複数借入を持てる融資ポートフォリオを実装した。

融資種別：

- 運転資金借入
- 長期借入
- 緊急融資

返済方式：

- 満期一括返済
- 元金均等返済

金利は次の構造とした。

```
年率 = 基準金利 + 信用スプレッド + 条件加算
```

基準金利、信用区分別スプレッド、緊急融資加算、財務制限条項違反加算、延滞履歴加算等は中央パラメータ化した。

### 銀行信用

銀行信用スコアは0～100で、判断時点で利用可能な情報だけを使う。

主な入力は以下のとおり。

- 現金余力
- 営業CF
- 収益性
- 利払能力
- 借入残高とレバレッジ
- 自己資本比率
- 返済実績
- 延滞履歴
- 顧客信頼
- 納期信頼性

銀行が未来の価格や将来実績を知る設計にはしていない。

信用区分はA～Eとし、借入可否、借入限度、金利スプレッド、緊急融資への移行へ接続した。

### 借入限度額

借入限度は固定額ではなく、次の要素から算出する。

- 適格売掛金
- 使用可能原料在庫
- 輸入未着原料
- 完成品在庫
- EBITDA相当の収益力
- 自己資本
- 既存借入残高
- 信用区分
- 延滞、債務超過、支払不能

担保掛目の初期値は、売掛金70%、使用可能原料40%、未着輸入原料15%、完成品30%とした。これらは将来校正対象である。

### 財務状態の区別

次の状態を区別した。

- healthy
- watch
- stressed
- covenantBreach
- paymentArrears
- insolvent
- paymentDefault

特に、赤字、債務超過、現金不足、支払延滞、支払不能を同じ状態にしなかった。債務超過でも支払を継続できる場合があり、逆に純資産がプラスでも現金がなければ支払不能になり得るためである。

### MASSの破綻経路

Phase 8B-1を接続すると、MASSではPhase 8Aの事業上の苦境が金融面へ波及した。

1. 過剰生産と在庫滞留
2. 安値販売と廃棄損
3. 営業CF悪化
4. 信用区分低下
5. 通常融資停止
6. 緊急融資利用
7. 国内買付停止
8. 支払延滞・支払不能

全5シナリオで、MASSはturn 1のみhealthy、turn 3以降は31／32ターンでpaymentDefaultとなった。MASSを救済するための会社別ハードコードは行っていない。

### 既存テストとの矛盾

Phase 6.3時代のテストには、「全社が自社養殖だけで恒常的に完全自給しない」という前提があった。Phase 8B-1導入後、支払不能となったMASSが国内原料を買えなくなり、このテストが1件失敗した。

これは融資ロジックのバグではなく、古いテスト前提と新しい経済構造の不整合であると判断した。

テストを次の2種類へ分割した。

- 健全企業が理由なく恒常的完全自給にならないこと
- 支払不能企業では、説明可能な資金制約がある場合に調達停止を許容すること

MASSという会社IDを特例扱いせず、財務状態と資金制約だけで判定するよう修正した。

## 6. Phase 8B-2A：設備投資案件と建設中勘定

### 設計目的

設備投資を「意思決定した瞬間に能力が増える処理」にせず、複数四半期にわたる案件として実装した。

状態は次の6種類。

- proposed
- approved
- underConstruction
- suspended
- completed
- cancelled

基本的な流れは次のとおり。

```
提案 → 承認 → 第1回支払・着工 → 工程進行 → 完成 → 固定資産振替
```

資金が不足すると、未着工案件は承認済みのまま待機し、建設中案件は中断する。資金が回復し、再開判断が行われた場合に工事を再開できる。

### 標準投資案件

次の6種類を実装した。

- HOSO加工ライン増設
- PD加工ライン増設
- VAP加工ライン増設
- 冷凍・冷蔵倉庫増設
- 品質管理設備
- 排水・環境対応設備

予算、標準工期、分割支払比率、固定資産区分、将来能力効果のメタデータを中央パラメータに集約した。

現時点の予算は約1.2～6.0百万USDであり、将来の本格校正対象である。

### 分割支払と建設期間

工程支払は全額支払方式とした。

- 必要額を全額支払える：工程が1段階進む
- 全額支払えない：支払なし、工程進行なし
- 建設中ならsuspendedへ移行
- 支払済みCIPは維持

標準工期は単なる暦期間ではなく、「支払と工事が成功した四半期数」で判定する。1四半期中断すれば、完成も原則1四半期遅れる。

### 資金配分

設備投資は裁量的支出とし、Phase 8B-1の資金繰り確定後の残余現金から支払う。

```
設備投資可能額 = max(0, 資金繰り確定後現金 − 最低現金準備額)
```

最低現金準備額は10百万USDの暫定値とした。

支払優先順位は次のとおり。

1. 建設中案件
2. 中断案件の再開
3. 承認済み未着工案件
4. 新規承認案件

同順位では承認時期、明示優先順位、案件IDによって決定論的に処理する。

### 建設中勘定と投資CF

設備投資支払時の会計処理：

- 現金：減少
- 建設中勘定：増加
- 投資CF：マイナス
- PL：影響なし
- 利益剰余金：影響なし

完成時の会計処理：

- 建設中勘定：減少
- 固定資産：増加
- 現金：変化なし
- PL：影響なし
- CF：変化なし

完成時の固定資産振替を投資支出として再計上しない。

### 三段クローズ

Phase 8B-1の資金繰りを再実装せず、次の三段構造で接続した。

1. 既存のcloseQuarterWithFinancingで資金繰りを確定
2. 資金繰り確定後の現金から設備投資可能額を計算
3. financing adjustmentとcapex adjustmentを使って最終財務諸表を確定

capex活動がない場合にPhase 8B-1の結果と完全一致するかを、受入前に追加確認した。

### 能力効果との分離

Phase 8B-2Aでは、完成設備の稼働可能四半期を記録するが、次の効果はまだ発生させない。

- 生産能力増加
- 保管能力増加
- 品質改善
- 環境対応効果
- 追加人員
- 固定費増加
- 新規設備の減価償却

これらはPhase 8B-2Bで接続する。

通常autoPolicyも設備投資を提案しないため、既存5社の8／32ターン結果は不必要に変化しない。

## 11. 本日の総括

本日の開発で、ShrimpX V2は「業績を計算するシミュレーター」から、「業績、信用、資金、投資が相互に制約し合う経営ゲーム」へ大きく近づいた。

特に重要なのは、財務諸表が後から表示される成績表ではなくなったことである。利益が出ても売掛金や在庫が増えれば現金は減る。現金が減れば信用と借入余力が悪化する。借入できなければ調達が止まる。設備投資を決めても、支払えなければ着工・完成できない。

この因果関係こそ、ShrimpXが研修用ビジネスゲームとして提供すべき学習体験の中心である。

一方で、現時点では完成設備の能力効果、自動会社の投資判断、完全な支払順位、再建金融、全体係数の校正は未完成である。今後はPhase 8B-2Bで設備投資の便益と負担を接続し、その後の長期シミュレーションで、投資過多、供給過剰、低稼働、財務悪化という経営上の連鎖まで再現していく。
