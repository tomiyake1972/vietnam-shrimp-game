## 2. 機能の要点

### 管理者指定の年間配当（D1）
- Management Console のバランス調整で配当性向を指定すると、PLAYER会社でも Standard AI会社でも同じように適用される。
- Q4決算の確定後に、その年度の Q1〜Q4 の税引後純利益の符号付き合計を基準に精算する。
- 年間目標 = max(0, 年間純利益) × Q4時点で有効な指定率。
- 年度内に既に支払った配当は差し引く。実支払は既存の上限 min(現金, 分配可能利益) を超えない。
- 0%の明示指定と「未指定」は別物として扱う（0%は「配当しない」という指示として記録される）。
- PLAYER が配当欄を一切触らなくても適用される。

### 提出・保存の競合対策（O1）
- 提出・保存は「読んだ正本の revision を申告し、食い違えば拒否する」方式（CAS）。
- 古い画面・別端末・GMの保存が、新しいPLAYER提出を上書きで消すことはない。
- 複数PLAYERが同じTurnへほぼ同時に提出しても両方残る。
- Console内PLAYERの「意思決定を確定」は、サーバ保存が成立してから確定表示になる（保存中は「保存中…」でボタンが無効）。
- 競合したら理由を表示して未確定へ戻す。再読み込みしてからやり直す。

### 市場集中による価格低下（Crowding）
- 販売モデルで `tiered-v200-crowding-v1` を選んだRunだけで動く。既定は従来モデル（`legacy-waterfall-v1`）のまま。
- 正式P1: threshold 1.00 / lambda 0.60 / gamma 1.00 / floor 0.82 / protectedExternalShare 0.20。
- 価格形成の診断は保存形式 v9 として履歴に残り、保存・再開・監査Excelへ通る。
- Crowding を使わないRunでは診断キー自体が作られない（v8以前と同じ形）。

### INT-1 で直したUI（詳細は `docs/int1/ui_issues.md`）
- 新工場建設カードが「生産能力を増加させません」と表示していたのを、Engineの能力値とランプアップから作った説明に直した。
- COMMERCIAL GROWTH で、AIの参考判断とPLAYER実績が区別なく並んでいたのを、系列名・注意書き・決定者列で区別した。
- 無効な数値を含む提出を、保存前に拒否するようにした（従来は無言で0に置き換えたり行が消えていた）。
- **商品別（HOSO/PD/VAP）の受注残**を、販売計画・生産計画の画面で見られるようにした。納期超過・当期納期・将来納期を分けて表示する（集計は既存のエンジン側モジュールをそのまま使用）。
- **前四半期の借入結果・緊急融資**を PLAYER の FINANCE 画面に出した。申請額・実行額・減額や否認の理由・緊急融資の実行有無と適用金利を表示する。記録が無い場合は「未取得」と出し、残高から推測しない。
- **営業人員の採用上限超過**を、提出・確定の時点で拒否するようにした（従来はGMがTurnを進めた時に止まり、PLAYER自身では直せなかった）。
- **入力値が無言で別の値に変わらない**ようにした。負数・範囲外はその場で0や上限へ丸めず、提出前の検証が理由つきで止める。
- 未確定の下書きが失われた場面で、その事実と「もう一度入力が必要なこと」「確定済みは失われないこと」を画面に明示した。

## 3. 既知の制限

### 運用で回避するもの
1. **未確定の下書きは再読み込みで消える。** 下書きはタブ内のメモリにしか無い。確定済みの意思決定はサーバに保存され残る（O1）。→ 入力途中でページを再読み込みしない。長い入力は確定を分けて行う。失われた場面では画面にその事実と再入力の必要が出る。
2. **Console内PLAYER画面を開いたまま別タブでGMが進行した場合、表示が古いままになりうる。** Independent Player は4秒ごとに自動更新される。古いTurnの提出自体はサーバが拒否する（`STALE_TURN`）ので、誤った値が計算に入ることはない。→ Console内PLAYERは「経営管制室へ戻る」→「この会社を操作」で開き直す。
3. **輸入代金の支払時期は2画面に分かれている。** 到着予定四半期は輸入発注セクション、買掛金の決済サイトは Decision→情報 画面の自社状態パネル。1画面にまとめた表示は無い。
4. **保存が失敗したTurnは失われる。** Console は失敗を明示して以降の進行を無効化するため気づかないまま進むことはないが、そのTurnは再実行になる。
5. **任意の過去Turnへ戻すことはできない。** 復旧は「最後に保存が成立した地点からの再開」だけである（詳細は `docs/int1/staging_deployment_plan.md` §5）。
8. **TSV は暫定的な参考指標。** 単独で勝敗を判定できるとは確認できていない。TSV・配当価値・会社価値・EV・参照CF は最終Turn（asOfTurn=32）の1点のみ算出され、Turn別の内訳は取得できない。

### 環境上の制限
9. **`npm run build` はこの環境で完了しない。** TypeScriptコンパイルは成功するが、"Collecting page data" 段階で V1 の既存route（`/api/game/[gameCode]/admin/reset` 等）が `STAGING_KV_REST_API_URL` 未設定で停止する。開発日誌に記録済みの既存事象であり、今回の統合内容とは無関係。
10. **AI経営説明（Claude API）は `ANTHROPIC_API_KEY` が無い環境では必ず失敗する。** 既存のエラー表示になるだけで、ゲーム進行には影響しない。
