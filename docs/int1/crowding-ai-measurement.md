# Standard AI への混雑度接続と32Turn回帰の実測

- 日付: 2026-10-12
- 判断: 三宅さんの指示「① 混雑度・シェア帯だけを AI にも使わせる」による
- 基点: commit 996bac1（任意期限前返済の修正済み・公開競合情報①②③まで実装済み）

## 1. 背景（調査でわかったこと）

Standard AI の observation には、**個社単位の競合情報が1つも無い**。
types.ts 冒頭も「未来のシナリオ・他社の非公開状態が一切混入しえない」と明記している。

唯一の競合概念は商品別の総供給圧力（`productSupplyPressureByProduct`、
5社提示量÷需要の EWMA）で、これは `growthPressure` が**成長ブレーキ**として
使うだけであり、「どの市場を避けるか」には使っていなかった。

一方、市場×商品の混雑度（crowding ratio）はエンジン側に既に存在し、
価格の下押しとして実際に効いている。受講者へ公開するのはこの値である。

## 2. 実装

### 2.1 公開チャネルを1本にした

抽出は `publicCompetitorSnapshot.crowdingRatioByCell` の1箇所だけ。
`PublicMarketInfo.observedCrowdingRatioByCell` に載せ、
受講者画面の混雑度帯と Standard AI の観測値はどちらもここから作る
（A-8 の開始時基準価格と同じ方針。どちらか一方だけが違う値を見ることを構造的に防ぐ）。

### 2.2 中立 policy では公開しない（CRWD-14 を守るための修正）

当初の実装は、`crowdingDiagnostics` があれば常に混雑度を公開していた。
これにより既存テスト CRWD-E2E-2
「中立 policy を明示しても結果は Crowding 未指定と同一（CRWD-14）」が落ちた。

原因は、中立 policy（`lambda=0 / floor=1`）でも診断自体は記録されるため、
AI がそれを見て配分を変えてしまうこと。中立 policy では混み合っても
成約価格は一切下がらないので、

- 受講者には「混雑のマスは価格が下押しされます」と**嘘を伝える**ことになり
- AI は**避ける理由の無いマスを避ける**ようになる

いずれも誤りである。そこで `lambda > 0 かつ floor < 1` のとき、
すなわち markdown が実際に効きうるときだけ公開するようにした。
これで CRWD-14 は維持される（テスト CA-8 で固定）。

### 2.3 AI の使い方

市場配分の機会スコアに次の係数を掛ける。

```
factor = 1 / (1 + crowdingAvoidanceWeight × max(0, 混雑度 - 1))
```

- 混雑度 1.0 以下、観測不能、weight = 0 のときは必ず 1（無補正）
- **`crowdingAvoidanceWeight = 0` にすれば、この機能を入れる前と完全に同一の配分になる**
- 既定値 0.6（混雑度1.5のマスの機会スコアを約77%に下げる水準。
  既存の供給圧力ブレーキ `supplyPressureFullBrake = 1.5` と水準を揃えた）
- どれだけ混雑しても係数は0にならない（市場を完全に捨てる判断はしない）

価格式・成約配分・crowding の markdown 自体は一切変更していない。

## 4. 申し送り（未判断の論点）

### 4.1 CONSV だけ -18.3% と大きい

他4社が ±3% 以内なのに対し CONSV だけ大きく下がっている。
原因は未特定（**未実測**）。混雑を避けて移った先の採算が、
避けた markdown より悪かった可能性があるが、確認していない。

### 4.2 5社合計の価値がやや減っている

全社が混雑を避けると、避けた先の市場の採算が元より低い場合があり、
markdown の回避分より失う貢献のほうが大きくなることがある。
`crowdingAvoidanceWeight = 0.6` は最初の設定値であり、校正していない。

研修バランスとして調整が必要なら、候補値（0.3 / 0.6 / 1.0 など）での
32Turn比較を実測して出せる。`0` にすれば接続前と完全に同一へ戻せる。
