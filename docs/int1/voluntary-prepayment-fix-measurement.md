# 任意期限前返済の修正と32Turn回帰の実測

- 日付: 2026-10-12
- 対象: `app/lib/v2/financing/liquidityClose.ts`
- 判断: 三宅さんの指示「案1（エンジンを修正し32ターン回帰を実測）」による
- 基点: commit `50b0997`

## 1. 不具合の内容

`applyWaterfallAcrossPortfolio` は任意期限前返済の原資を、必須元本の原資の
払い残り（`remainingPrincipal`）から取っていた。

呼び出し側で必須元本の原資は `min(availableForPrincipal, scheduledPrincipalDue)` と
予定返済額ちょうどに上限されているため、予定返済を全額払えた場合の払い残りは常にほぼ0。
その結果 `voluntaryRemaining = min(請求額, ほぼ0) = ほぼ0` となり、
**任意期限前返済は請求額にかかわらず一度も実行されなかった。**

## 2. 修正内容

必須元本の原資と任意返済の原資を別枠にした。

- `applyWaterfallAcrossPortfolio` に `availableForVoluntaryPrincipalUsd` を追加
- 呼び出し側で `voluntaryPrincipalBudget = max(0, availableForPrincipal - mandatoryPrincipalBudget)`
- 緊急融資を引いた期は `0`（利息＋予定元本を自力で払えない期に繰上返済はあり得ないため）
- 当期に実行した融資（`originationPeriod === period`）は対象外
  （当期実行分には当期の利息が付かないため、借りて即返すだけの無コスト循環を防ぐ）

変更していないもの: 金利式、予定返済額の算出、延滞判定、緊急融資の判定、
Standard AI の繰上返済ポリシー（`cash > 目標最低現金 × 2.5` のとき `cash - 閾値` を希望）。

## 6. 申し送り（未判断の論点）

Standard AI の繰上返済ポリシーは `voluntaryPrepaymentMultiple = 2.5`
（目標最低現金の2.5倍を超える現金を全額、借入残高を上限に繰上返済へ回す）。
このポリシー自体は今回変更していないが、修正前は**実行されていなかったため効いていなかった**。
有効化された結果、4.3 のとおり会社別の最終評価が大きく動いている
（BAL -33.8% / CONSV +26.7%）。

これはパラメータ調整の問題であり、エンジンの不具合ではない。
研修バランスとして 2.5 が妥当かどうかは別途の判断が必要。
