# ShrimpX V2.00 研修試行候補 — 操作手順

更新: 2026-10-07 JST / 対象: ローカル統合候補（未配備）

画面上の文言とボタン名は、統合候補のコードから確認した実物です。

## 1. 新規Run作成と販売モデル選択（GM）

1. 管理トークンでログインする。
   - `/v2/company-lab/play/login` を開き「管理トークン」を入力して「ログイン」。
   - Setup画面の右上「🔐 管理者ログイン」からも開ける（別タブで開き、入力中の設定を失わない）。
2. `/v2/management/setup` を開く。
3. **Scenario** を選ぶ。研修試行の技術確認では Dynamic Scenario 2 を使った。
4. **Seed** を入力する（「生成」ボタンでランダム生成も可）。同じ seed・同じ設定なら結果は決定論的に一致する。
5. **会社ごとの経営モード** を選ぶ。人が操作する会社を `PLAYER`、残りを `STANDARD_AI` にする。
6. **販売市場モデル** を選ぶ。
   - 既定は「従来市場モデル」（`legacy-waterfall-v1`）。
   - 市場集中による価格低下を入れる場合は「三層顧客価格モデル V2.00＋市場集中価格下落」（`tiered-v200-crowding-v1`）を選ぶ。
   - **一度作ったRunのモデルは後から変えられない。** 保存・再開してもそのRunのモデルは選んだものが維持される。
7. 必要なら Run 名を入れる。
8. 「この設定で開始」を押す。Management Console（`/v2/management?run=...`）へ移動する。
9. Console の上部で、販売市場モデルが選んだとおりに表示されていることを確認する。

## 2. 管理者指定の年間配当を設定する（GM）

1. Console の「バランス調整」を開く。
2. 配当性向（%）を入力する。
3. 適用方法を選ぶ。
   - `continuing`（継続）: 指定Turn以降ずっと適用。研修では通常これ。
   - `perTurn`（単発）: 指定した1Turnだけ。
4. 「適用」を押し、「保存しました」の表示を確認する。
5. 設定は **次の未実行Turnから** 効く。確定済みTurnの記録は書き換わらない。
6. 年度末（Q4）の精算結果は Console の「年間配当」パネルで会社別に確認できる。
   - 「0%」と「未指定」は別表示になる。0%は「精算して0だった」として記録される。

## 3. PLAYER の提出（2通り）

### A. Management Console 内で GM が代理操作する
1. Console の会社一覧で、その会社の「この会社を操作」を押す。
2. PLAYER Company Workspace が開く。ヘッダの `Turn` が現在のTurnであることを確認する。
3. 「意思決定」タブで入力する。
4. 「この内容で意思決定を確定」を押す。
   - 押すとボタンが「保存中…」になり無効化される。**サーバ保存が成立してから「意思決定済み」になる。**
   - 競合した場合は赤字で理由が出て未確定へ戻る。画面を再読み込みしてからもう一度確定する。
   - 無効な数値があると「入力に無効な値があるため確定できません（値は保存していません）」が出る。該当項目を直す。
5. 「経営管制室へ戻る」で Console へ戻る。
6. 進行後に同じ会社を操作するときは、必ず Console から「この会社を操作」で開き直す（古いTurnの表示を避ける）。

### B. 別端末の Independent Player が提出する
1. GM が Console の参加者パネルでその会社の参加リンクを発行する。
2. 参加者へリンクを渡す。**再発行すると旧リンクは無効になる。**
3. 参加者はリンクを開くと `/v2/play/workspace` に入る。Cookie で復帰できるため、閉じて開き直しても同じ席に戻る。
4. 入力して「この内容で提出する」を押す。提出後は「GMの進行待ち」表示になる。
5. 画面は4秒ごとに自動更新され、GMがTurnを進めると次Turnへ自動的に切り替わる。
6. 無効な数値を含む提出はサーバが拒否する（値は保存されない）。直して再提出する。

## 4. Turn 進行・保存・再開（GM）

1. 全てのPLAYER会社が提出済みになると「1 Turn」ボタンが押せる。
   - 未提出の会社があるうちは押せない（参加者パネルで誰が未提出か分かる）。
2. 「1 Turn」を押す。Turnカウンタ（`N / 32`）が増える。
3. 進行のたびにサーバへ保存される。保存は revision ベースのCASで、他の保存と競合した場合は拒否されて理由が出る。
4. 保存が認証切れ（HTTP 403）で失敗した場合は、エラー内の「こちらから再ログイン」を押す。
   - 新しいタブで管理ログインし、終わったらこのRunへ自動的に戻る。
   - 戻ったら「1 Turn」を押し直すと保存を再試行する。
5. **再開**: Console を再読み込みしても、保存済みのRunから続きを進められる。
   - 直前のTurnまでの履歴は保存形式の仕様で直近4Turn分へ間引かれる。分析用の全Turnデータは別に保持される。
6. 32Turn目まで進めるとゲーム終了になり、Final Results が出る。以降の提出はサーバ側で拒否される。

## 5. PLAYER が意思決定時に見られる情報（INT-1 で追加した導線）

| 見たいもの | 場所 |
| --- | --- |
| 商品別（HOSO/PD/VAP）の受注残 | 「意思決定」タブ → SALES 画面および PRODUCTION 画面の先頭「受注残（未履行の確定受注）— 商品別」。受注残合計／納期超過／当期納期／将来納期／状態を商品別に表示し、市場×商品別の上位内訳も出る |
| 受注残の全件（市場×商品別） | 「意思決定」タブ → 情報 画面の「受注残（未履行契約）の内訳（市場×商品別）」 |
| 前四半期に実際に借りられた額 | 「意思決定」タブ → FINANCE 画面の先頭「前四半期の借入結果・緊急融資」。申請額／実行額／減額・否認された額／適用金利／記録されている理由 |
| 緊急融資の実行有無・適用金利 | 同じパネルの「緊急融資」欄。記録が無い場合は「未取得」と出る（残高から推測した値は出さない） |
| 買掛金（輸入代金）の決済サイト | 「意思決定」タブ → 情報 画面の自社状態パネル |
| 輸入の到着予定四半期 | 「意思決定」タブ → PROCUREMENT 画面の Import Procurement セクション |

### 入力でエラーが出たとき
- 「入力に無効な値があるため提出できません（値は保存していません）」が出たら、メッセージに挙がった項目を直して再提出する。値は保存されていないので、同じTurnのまま直せる。
- 「営業人員の採用は1四半期あたり N 人までです」が出たら、採用人数を N 以下にする。これも提出前に止まるので同じTurnのまま直せる。
- 負数や範囲外の数値はその場で 0 や上限に書き換わらない。打った値がそのまま残り、提出時に理由つきで止まる。

## 6. 出力物

- Console から監査用Excel（`ShrimpX_StandardAI_Audit_<runId>_32Q.xlsx`）を出力できる。Crowding の価格形成診断も含まれる。
- Final Results は5社比較とダウンロードが利用できる。
- 分析画面 `/v2/management/analysis/commercial-growth` で成長の制約要因を見られる。
  - PLAYERが決めたTurnを含む会社では、①〜④が「AI参考値」であり、PLAYERの実提出量は未取得である旨の注意書きが出る。表の「決定者」列でTurnごとの決定者が分かる。
