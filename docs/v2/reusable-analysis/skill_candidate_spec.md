# スキル化の草案（SAI-3B-2時点、未確定）

**重要**: これは三宅さんの指示§10「スキルとしてまだ確定させない」に基づく
**草案（draft）**であり、正式なskillとして配布・固定化するものではない。
SAI-3B-2完了後の三宅さんのレビューを経て、必要であれば別ラウンドで
正式なskill定義に格上げする。

## 1. 想定するスキルの名称・目的（仮）

- 仮称: `sim-kpi-excel-dashboard`
- 目的: 「複数seed×複数会社×複数四半期の時系列ログ（CSV/JSONL）」を
  入力として、経営KPIダッシュボード付きのExcelブックを生成する、
  ゲーム/シミュレーション横断で再利用可能な手順。

## 2. 汎用化できている部分（このラウンドで確認済み）

- `CompanyQuarterKpiSpec`レジストリパターン（KPI定義とレンダリングの分離）。
- 3層構造（Layer1見出しmedian／Layer2統計／Layer3個別詳細）という表示設計。
- `injectNativeChartsMultiSheet`によるマルチシートのネイティブグラフ注入
  という、ExcelJSにネイティブグラフ機能が無いことへの一般的な対処法。
- 「同一パラメータの複数値を横断比較し、乖離が始まる最初の時点を検出する」
  という比較ロジック（`buildHeadcountDivergence`のパターン。パラメータが
  「営業人数」である必要はない）。
- 会社別/条件別の固定配色パレットパターン（`CANONICAL_COMPANY_ORDER`+
  `COMPANY_COLOR_HEX`）。
- 欠損値を0にせず`undefined`のまま最後まで伝播させる、という全レイヤー
  共通の契約（`data_contract.md`参照）。

## 3. ShrimpX固有で、汎用化にあたり要検討な部分

- 商品区分（hoso/pd/vap）・市場区分（CN/US/EU/JP/OTHER）という固定enumへの
  依存（`kpi_catalog.md`参照）。他ゲームでは異なる区分になるため、
  スキル化する場合はこれらを設定可能なパラメータとして外出しする必要がある。
- 「HOSO換算トン」という単位変換の概念。
- 「営業工数制約」「与信・underwriting」「default判定」など、ShrimpX V2の
  ビジネスロジック固有のイベント区分。これらは「イベント種別を検出して
  時系列に注記する」という枠組みとしては汎用化できるが、具体的なイベント
  名・閾値は個別ゲームごとに再定義が必要。

## 4. スキル化する場合に必要な追加設計（未着手・課題として記録）

1. KPIレジストリの外部設定化: 現状`CompanyQuarterKpiSpec`配列は
   TypeScriptのコード内に直書きされている。スキル化する場合は、JSON/YAML等の
   設定ファイルからKPI定義を読み込めるようにする必要がある。
2. 入力データ契約の抽象化: 現状「quarter-summary.csv」等、SAI-3A固有の
   ファイル名・列名にハードコードされている。スキル化する場合は、
   「会社×seed×turn単位の時系列レコード」という抽象的なデータ契約
   （インターフェース）を定義し、個別ゲームごとのアダプタ（CSVパーサー）
   を差し替え可能にする必要がある。
3. 市場シェア・乖離検出など、ドメイン固有ロジックのプラグイン機構。
4. 実際に2つ目以上のドメイン（ShrimpX以外のシミュレーション）へ適用してみて、
   「本当に再利用できるか」を検証する（現時点ではShrimpX V2でしか
   使っていないため、汎用性の主張は理論的なものにとどまる）。

## 5. このラウンドでの結論

SAI-3B-2では、上記の汎用化可能な設計パターンをコード内に**実装として
体現**したが、それらを抽出して再利用可能な設定駆動のスキルへ変換する
作業（上記4項目）は行っていない。三宅さんの指示どおり、今回はまだ
「スキルとして確定・配布」する段階ではないと判断し、このドキュメントは
次にスキル化を検討する際の出発点（草案）としてのみ位置づける。
