# SAI-4 将来設計メモ — 「会社性格」と「役員性格」の二層分離（§7、実装対象外）

対象: `feature/v2-sai4-heterogeneous-standard-ai`（`feature/v2-sai3b-excel-analysis`
から分岐）。本メモは三宅さんの実装指示§7「将来構想に向けた設計メモ（実装は
今回対象外）」への対応であり、**コードは一切含まない**。今回実装した
`ManagementProfile`（会社性格レイヤー）と、将来構想されている「役員個人の
性格」を混同しないための整理だけを目的とする。

## 1. 今回実装したもの（会社性格レイヤー）とその位置づけ

`app/lib/v2/companyLab/standardAi/managementProfile.ts`の`ManagementProfile`は、
「1社が組織として持つ、四半期をまたいで一定の経営性格」を表す。5プロファイル
（balanced/growth/conservative/valueAdded/opportunistic）はいずれも「会社全体の
判断傾向」であり、以下の性質を持つ:

- 会社1社につき常に1プロファイルだけが適用される（決定は単一の合成された
  `StandardAiParameters`から生成される。複数の「声」が競合・合議する構造では
  ない）。
- 標準AIの意思決定ロジック・情報境界・安全ガードは一切変えない
  （`managementProfile.ts`冒頭のコメント参照）。
- 会社IDとプロファイルの対応は固定（`MANAGEMENT_PROFILE_BY_COMPANY_ID`）。

## 2. 将来構想「役員個人の性格」との違い

三宅さんの構想（本メモが前提とする将来像）は、これとは別軸の話である:
「1社の中に複数の役員（営業本部長・CFO・生産本部長・戦略担当・CEO）がいて、
各役員がそれぞれ異なる視点・優先順位で同じ状況を評価し、最終的にCEOが
それらを統合（synthesize）して1つの意思決定にする」という、**役員間の
合議・対立構造**である。三宅さんの closing remark（今回の指示の末尾）が
明示するとおり、「B社＝営業本部長視点、C社＝CFO視点」に相当する対立軸を、
今回はまず「会社レベルの性格」として体現しており、将来は「1社の中の
営業本部長 vs CFOの対立」として体現し直すことが構想されている。

想定される役員ロールと、今回の会社プロファイルとの対応関係（あくまで
出発点となる仮の対応であり、確定した設計ではない）:

| 役員ロール | 今回の会社プロファイルとの近さ | 想定される視点 |
|---|---|---|
| 営業本部長 | B社（growth）に近い | 販売数量・市場シェアを最優先。値引き・輸入依存にも寛容。 |
| CFO | C社（conservative）に近い | 利益率・資金繰りの安定を最優先。値引き・輸入依存・性急な固定費増を嫌う。 |
| 生産本部長 | A社（balanced）的な「安定志向」に近い | 特定商品への偏りより、既存設備・既存人員の安定稼働を志向。将来的にはA社よりもさらに「変化を嫌う」方向にチューニングされる可能性がある。 |
| 戦略担当 | D社（valueAdded）とE社（opportunistic）の中間 | 高付加価値化（D社的な視点）と機会追求・タイミング（E社的な視点）の両方を状況に応じて使い分ける、複合的な役割になる可能性が高い。1つの固定プロファイルには単純化できないかもしれない。 |
| CEO | 上記4者の統合者（synthesizer） | 単独の「性格」を持つというより、他4者の意見の重み付け統合・最終責任者という役割そのものが特殊であり、今回の5プロファイルのどれとも直接対応しない。 |

## 3. なぜ今回、両者を混同してはいけないのか

1. **軸が違う**: 会社性格は「会社×時間」で固定される構造的な傾向（同じ会社は
   今期も来期も同じ性格）。役員性格は「会社×役員×決定領域」で変わりうる、
   より粒度の細かい構造になる可能性が高い（例: 同じ会社でも、販売領域の
   決定は営業本部長寄り、資金領域の決定はCFO寄り、といった「決定領域ごとに
   支配的な視点が変わる」設計もありうる）。今の`ManagementProfile`は
   「会社全体に単一のバイアス値を適用する」設計であり、この粒度の違いを
   最初から吸収できる構造にはなっていない。
2. **単一の声 vs 複数の声の合議**: 今回の実装は「1つの合成されたパラメータ
   セットで1回だけ意思決定を計算する」。役員性格構想は「複数の視点で評価
   した上で統合する」ため、根本的に評価回数・統合ロジックが異なる
   （将来、Claude APIによる役員間対話・CEOによる統合提案といった、まったく
   別の技術要素が必要になる可能性がある。これは三宅さんの指示§12で明示的に
   今回のスコープ外とされている）。
3. **今、混同すると後戻りが困難になる**: もし今回`ManagementProfile`の中に
   「役員視点」のような概念を先取りして埋め込んでしまうと、将来「1社の中で
   複数役員が対立する」構造を作る際に、会社レベルのバイアスと役員レベルの
   バイアスが二重に効いてしまう（例: B社のgrowthバイアスに、将来営業本部長
   バイアスが重なって、想定より過大な数量積み増しになる）といった、原因の
   切り分けが困難な混線を生む。今回、両者を明確に別レイヤーとして「今は
   会社性格だけ」と割り切ったのは、この混線を将来発生させないための予防
   措置である。

## 4. 将来、役員性格レイヤーを追加する場合に検討すべき論点（メモ、結論ではない）

以下はあくまで将来の設計検討のための論点整理であり、今回結論を出すもの
ではない。

- **合成方法**: 役員ごとの提案パラメータを、CEOロールがどう統合するか
  （単純平均、重み付け、閾値超過時のみ介入、等）。「今回のManagementProfile
  のように、決定論的な数式で合成する」方式と、「Claude API等を使い、役員間の
  自然言語での対話・説得を経てCEOが判断する」方式は、決定論性・再現性・
  コストの観点で大きく異なる。標準AIの「決定論的で同一seed・同一入力なら
  常に同一結果」という前提（policy.ts冒頭のコメント参照）を維持するなら、
  少なくとも自動テストプレイ・バランス調整用のモードでは前者（決定論的合成）
  を維持する必要がある。
- **決定領域ごとの支配役員**: 全ドメイン（販売・生産・調達・労務・資金・
  設備投資）を同じ「合成された性格」で決めるのか、ドメインごとに支配的な
  役員を変えるのか（例: 販売領域は営業本部長の重みを高くする）。
- **対立の可視化**: 三宅さんが将来望んでいるのが「対立構造」であるなら、
  診断ログ（今回の`StandardAiManagementProfileDiagnostics`と同じ発想）に
  「どの役員がどの提案をし、CEOがなぜその提案を採用/却下したか」を記録する
  仕組みが必要になる。今回の`appliedBiasItems`（基準値→バイアス後の追跡）は、
  そのまま「役員提案→CEO採用後」の追跡にも転用できる設計になっている
  （StandardAiParametersを介した合成という骨格自体は再利用できる）。
- **会社性格との重ね合わせ**: 将来的に「A社（balanced企業文化）の中の
  営業本部長」と「B社（growth企業文化）の中の営業本部長」は、同じ役職でも
  異なる行動になるべきか（=会社文化が役員個人の性格に補正をかける）、
  それとも役員の性格は会社に依存せず固定か。これは経営戦略ゲームとしての
  設計判断であり、技術的な制約からは決まらない。

## 5. 現時点の結論

今回は`ManagementProfile`（会社性格）だけを実装し、役員性格レイヤーは
一切実装しない。将来役員性格レイヤーを追加する際は、本メモの論点を
出発点として、あらためて三宅さんとスコープ・合成方法を確認の上で
設計・実装する。
