# ShrimpX V2 市場・価格形成モジュール Phase 1（v0.1）

`feature/v2-market-pricing` ブランチで実装した、V2の市場・価格形成モジュール（`app/lib/v2/market/`）の設計記録。

## 1. モジュールの責務と非責務

### 責務（このPhaseで実装した範囲）

- 4か国（エクアドル EC・インド IN・インドネシア ID・ベトナム VN）の国別HOSO FOB価格の算出
- ベトナム国内未凍結原料価格の算出（国際HOSO価格とは別計算）
- PD・VAPプレミアムの算出（国別HOSO価格への上乗せとして）
- 上記すべてについて、価格だけでなく変動要因・需給指標・理由コードを返す説明可能な出力

### 非責務（このPhaseでは実装していない。将来モジュールの責務）

- 画面（Next.js）・APIルート・Redis読み書き・実ゲームの作成
- 販売計画・成約・約定残（ContractBook）
- 工場・人員・自社養殖・輸入原料の実処理
- 信頼スコア・品質投資・品質事故・納品遅延
- 財務三表・借入・設備投資
- 生成AIによる解説文生成（本モジュールは理由コードという機械可読データまでを返す）
- 各社個別の調達意思決定（業界集計値としての `domesticProcurementIntent` のみを入力として受け取る）
- 放養コホート・生残率シミュレーション、期・国別の完全な収穫量計算（`production`は当期の確定値として入力で受け取る）
- イベント抽選（疾病・異常気象・貿易規制等。市場価格形成モジュール仕様書 v0.2 §12）
- 情報レベル別レポート生成（同 §14。GM・生成AIが理由コードから作る想定）
- 完全な数量ベース市場清算（同 §9.1のsoftmax原産地シェア配分と反復収束）

## 2. 入力と出力

呼び出し規約:

```typescript
const marketResult = calculateMarketQuarter(input, parameters, randomStream);
```

- `input: MarketQuarterInput` — 当期の国別供給・需要市場・ベトナム国内・PD/VAP需要
- `parameters: MarketParameters` — `MARKET_PARAMETERS_V1`（バージョン付きパラメータ定義）
- `randomStream: RandomStream` — V2 core（Phase 0）の決定論的乱数ストリーム

`calculateMarketQuarter` は `input`・`parameters` を一切変更しない純粋関数であり、同一の `input`・`parameters`・同一シードの `randomStream` からは常に同一の `MarketQuarterResult` を返す。

出力 `MarketQuarterResult` には、国別HOSO価格（前期比・需給圧力・理由コード付き）、世界需給バランス、ベトナム国内原料市場の清算結果、PD/VAPプレミアム（世界全体＋国別）、全体の理由コード一覧が含まれる。

## 3. 価格形成の順序

`calculateMarketQuarter` は、市場価格形成モジュール仕様書 v0.2 §11「ターン処理順序」のうちPhase1が対象とする範囲を、以下の順序で呼び出す。

1. 国別のコスト指数変化・輸出可能供給量の算出（`countrySupply.ts`）
2. 世界需要の算出（`globalDemand.ts`）
3. **Market Opening**（`hosoPricing.ts` の `openHosoMarket`）— 国別需給圧力 L_i・世界共通圧力 G を確定する。まだ価格には触れない。
4. **Market Clearing**（`hosoPricing.ts` の `clearHosoMarket`）— L_i・G・決定論的ショックから当期HOSO FOB価格を確定する。
5. ベトナム国内未凍結原料市場の清算（`vietnamRawMarket.ts`）
6. PD/VAPプレミアムの算出（`productPremium.ts`）

仕様書が指定する「Market Opening」→「Market Clearing」の二段階構造は、関数を明確に分離することで守っている。Openingは需給指標の確定のみを行い、価格計算はすべてClearingに閉じ込めている。

## 4. 国際HOSO価格とベトナム国内原料価格を分ける理由

市場価格形成モジュール仕様書 v0.2 §2「市場分離」原則、および§17不変条件「HOSO価格とベトナム国内原料価格が別フィールド・別計算として保存される」に対応するため、以下のように実装を分離した。

- `hosoPricing.ts` はHOSO FOB価格（国別・冷凍製品・輸出価格）のみを扱う。
- `vietnamRawMarket.ts` はベトナム国内の未凍結原料価格のみを扱う。国際HOSO価格を「上流」として一方向に参照する（HOSO価格 → 買付上限 → 国内原料価格）が、国内原料の需給状況が国際HOSO価格を書き換えることはない。
- 両者は別の型（`CountryHosoPriceResult` と `VietnamDomesticResult`）・別の理由コード体系を持ち、`MarketQuarterResult` 内でも別フィールドとして保持する。

これにより、国内原料市場の係数変更が国際HOSO価格の計算へ意図せず波及することを防いでいる。

## 5. PD/VAPプレミアムの考え方

全体実装計画書 v0.1 の対象商品定義（`Product = "hoso" | "pd" | "vap"`、§19）を踏襲し、PD・VAPはHOSO基準価格（国別）にプレミアムを加える形で価格形成する。

- ベースプレミアムは「世界全体の稼働率（PD/VAP需要 ÷ 4か国合算の加工能力）」から算出する。稼働率が基準値を上回れば逼迫（プレミアム拡大）、下回れば過剰（プレミアム縮小）となる。エクアドル・インドの加工能力が増えれば世界全体の能力が増え、稼働率が下がってプレミアムが縮小する（＝資料が想定する「エクアドル・インドのPD能力がゲーム後半で伸びる」影響を、能力を入力として与える形で表現している。期に応じた能力の伸び方自体は、このモジュールの外側＝呼び出し側のシナリオ設定の責務とする）。
- 国別には、その国のHOSO価格にベースプレミアムを乗せたうえで、`qualityScore`（品質評価）に応じた品質プレミアムを加算する。ベトナム・インドネシアの品質優位は、これらの国の `qualityScore` が高い場合に自動的に反映される（国名をコードにハードコードするのではなく、入力データとして与える設計）。
- HOSOでは原料高により相対的に不利なベトナム・インドネシア（country HOSO価格が高いまま）が、PD/VAPでは品質プレミアムにより一部相殺される、という仕様書の想定を、「country HOSO価格 + premium」という積み上げ構造の中で自然に表現している。

## 6. パラメータ調整箇所

すべての係数・初期値は `app/lib/v2/market/parameters.ts` の `MARKET_PARAMETERS_V1` に集約されている。計算ロジック側にマジックナンバーは存在しない。

主なパラメータ:

| パラメータ | 値 | 出典・状態 |
|---|---|---|
| 初期HOSO FOB価格（EC/IN/ID/VN） | 4.70 / 5.25 / 5.45 / 5.60 USD/kg | 仕様書§4.1。仮置き（実データ取得後に再校正） |
| 世界影響度ウェイト（EC/IN/VN/ID） | 0.45 / 0.25 / 0.18 / 0.12 | 仕様書§9.2・§16。プロトタイプ限定と明記 |
| ローカル圧力ウェイト／世界圧力ウェイト | 0.60 / 0.40 | 仕様書§9.2の簡易式 |
| 四半期価格変化率の上限 | ±20% | 仕様書§9.3で「未設定」とされる項目。Phase1新規・要校正 |
| 需給不均衡ウェイト／コスト変化ウェイト | 0.70 / 0.30 | Phase1新規・要校正 |
| 決定論的市場ショックの振幅 | ±2% | Phase1新規・要校正 |
| プロラタ最低引取比率 | 過去4Q平均×20% | 全体実装計画書 v0.1 §10.1。確定値として明記 |
| PD/VAPベースプレミアム比率 | 18% / 55%（HOSO価格に対する比率） | Phase1新規・要校正（仕様書に金額水準の記載なし） |
| 品質プレミアム感応度 | 品質スコア100点分でHOSO価格の+30% | Phase1新規・要校正 |

パラメータセットにはバージョン文字列 `parametersVersion` を持たせており、将来の係数変更は新バージョンの追加として行い、旧バージョンは削除しない方針（全体実装計画書 v0.1 §20に準じる）。

## 7. 後続の販売・調達・信頼モジュールとの接続点

- **販売モジュール**: `MarketQuarterResult.hosoPrices` / `pdPremium.byCountry[VN].finalPrice` / `vapPremium.byCountry[VN].finalPrice` を、市場別・商品別の販売価格の基準として参照する想定。
- **調達モジュール**: `MarketQuarterResult.vietnamDomestic.price` を国内原料の実効仕入単価の基準として、`VietnamDomesticInput.domesticProcurementIntent` を各社の調達計画から積み上げて供給する想定（Phase1では業界集計値のみ実装。会社別のプロラタ配分自体は調達モジュールの責務）。
- **信頼モジュール**: 現時点では未接続。`reliabilityScore`（`CountrySupplyInput`）は将来、信頼モジュールが会社別に持つ信頼スコアから国別・産地別の値へ集約されて渡される想定のプレースホルダとして用意している。
- **GM・生成AI解説**: `MarketPriceDriver` の理由コード群と、`localPressure`/`worldPressure`/`utilizationRatio`/`imbalance` 等の内訳値を、そのまま解説文生成の入力として使える設計にしている。

## 8. Phase1での単純化・未実装事項

- 国別供給（`production`・`exportCapacityRatio`）は当期の確定値として入力で受け取り、放養コホート・生残率からの内部シミュレーション（仕様書§5〜§7）は行わない。
- 需要側は「基礎需要（前期消費量）×景気指数×(1+人口増加率)」のみを実装し、季節性・在庫調整・価格弾力性・原産国選好・代替調達（仕様書§8）は実装していない。
- 国別への需要配分は、仕様書§9.1の完全なsoftmax原産地シェア配分ではなく、§9.2の簡易式が使う世界影響度ウェイト（EC45/IN25/VN18/ID12）を流用している。数量ベースの市場清算への移行は仕様書自身が「国別供給量と市場別需要量が安定して計算できた段階」を条件とする将来対応。
- ベトナム国内原料価格の買付上限計算は、為替（VND/USD）の項を省略し、USD単一建てで計算している（V2 coreに現地通貨単位が未定義のため）。
- 農家の期待原料価格形成（仕様書§6.2の0.50/0.30/0.20ウェイト）・放養反応（§6.3）は、パラメータとして値だけ保持し、計算には未使用（将来の養殖モジュールが利用する想定）。
- イベント抽選（疾病・異常気象等、§12）、情報レベル別レポート生成（§14）は未実装。
- `Market`型は全体実装計画書 v0.1 §19の定義と同じ値集合だが、本モジュール内での命名衝突を避けるため `DemandMarketId` に改称している（値は完全に同一）。

## 9. 主要な設計判断・仕様からの逸脱

- V2 coreのbranded type（`HosoEqTons`・`UsdPerHosoEqKg`・`Ratio`・`Score0to100`）をすべての数量・価格に使用している。景気指数・人口増加率・養殖コスト指数のような無次元係数はbranded type化せず、`assertFinite`による有限性検証のみのplain numberとした（物理単位を持たないため）。
- PD/VAPのベースプレミアムは、仕様書・全体実装計画書のいずれにも金額水準の記載がないため、HOSO価格に対する比率として実装した（原価連動性を確保するため。固定USD額ではない）。
- 内部計算では丸めを一切行わず（`roundUsdM`等のcore/units.tsの丸め関数は使用しない）、branded typeのスマートコンストラクタによる範囲検証のみを適用している。表示用の丸めは今回のスコープ外。
