## G. VAP ライン増設 CAPEX の出自と価格感度

### G-1. 出自（provenance）

`capex/parameters.ts:184-195`:

```
vapLineExpansion: 6,000,000 USD / +250 t/四半期 / 工期4Q（0.25,0.35,0.25,0.15）
                  竣工後準備 2Q / 建物25% 機械75% / 保守 1.0%/四半期
```

= **24,000 USD/t（四半期能力1トンあたり）**。

ソース上のコメントは「VAP は高付加価値・高複雑度設備で建屋要件もやや高いという想定」
「保守費率をやや高めに設定」のみで、**算出根拠・出典・実測は一切書かれていない**。
git 履歴でもこの値は初出コミット（capex parameters の新設時）から一度も変更されておらず、
校正記録は存在しない。他テンプレートは校正コメントを持つ
（例 `coldStorageExpansion` は「実装指示の目安 USD 1,500〜2,500 の中央付近になるよう校正」、
`hosoLineExpansion` は「PD より意図的に大幅へ安くしてある」）が、
**VAP ラインだけは根拠が取得不能**である。

**VAP 能力を増やす手段としても vapLineExpansion は経済的に支配されている**。

### G-4. なぜ価格が効かないのか

DS3 8seed の CAPEX 却下は **125 件すべてが同一理由**である:

```
同時進行中案件数が上限(3)に達しているため新規承認を見送り。
（capex/projectLifecycle.ts:156, params.maxConcurrentActiveProjectsPerCompany = 3）
```

| 会社 | 却下件数 | 内訳 |
|---|---:|---|
| JPQ | 45 | qualityControl 26 / newFactory 13 / pdMechanization 6 |
| CONSV | 37 | qualityControl 18 / newFactory 9 / pdMechanization 8 / hosoLine 2 |
| VAP | 33 | qualityControl 24 / newFactory 6 / pdLine 2 / **vapLine 1** |
| BAL | 10 | newFactory 6 / hosoLine 2 / pdMechanization 2 |
| MASS | 0 | — |

**資金不足・スペース不足・財務ゲートによる却下は 0 件。**
つまり CAPEX の可否を決めているのは価格でも資金でもなく、
**1社あたり同時 3 案件という枠**である。枠が埋まっている限り、
vapLineExpansion を無料にしても承認件数は増えない。

さらに VAP 社では枠の多くを `qualityControlEquipment`（24 件却下＝提案は出続けている）が
争っている。同設備は `capacityIncreaseTonsPerQuarter: 0`（能力を増やさない）ため、
**能力を増やさない案件が能力を増やす案件と同じ 3 枠を奪い合っている**。

### G-5. G の結論

1. VAP CAPEX 単価 24,000 USD/t に**算出根拠は存在しない**（取得不能）。
2. しかし**価格は現在 binding ではない**。50% にしても結果が動かない。
3. 実際の律速は (a) 同時進行案件上限 3 件（#04 Engine）と
   (b) 凍結・包装能力を Standard AI が拡張できないこと（#05、本体監査 C-3）。
4. したがって **VAP CAPEX 価格の変更は、現時点では優先度が低い**。
   先に (a)(b) を解いた後でなければ、価格変更の効果は測定できない。

## H. VAP の合理的規模の評価（32 / 40 / 45 / 50 kt/四半期）

### H-3. 分類

| 規模 | 区分 | 判定理由 |
|---|---|---|
| **32,000** | **A** | 現在 30,636。T30〜T32 の生産は 30,787 まで来ており、既存能力
（ライン 35,312 / freezing 42,750）と Worker +508 人で到達する。追加投資不要 |
| **40,000** | **B** | freezing 42,750 は足りる。不足はライン 4,688t のみで、
新工場 1 棟（22.0M・回収 1.0Q）で解消する。VAP 社は T32 で現金 388M・借入 0 なので資金は十分。
現行で届かない理由は資金でも経済性でもなく、**同時 3 案件枠と、序盤 21 四半期を

| **45,000** | **C** | freezing が 2,250t 不足する。新工場を建てれば freezing も +17,100 されるため
数字上は届くが、**Standard AI は freezing を能力として認識していない**
（`bindingCapacity.ts:22`）ため、freezing を理由に投資判断することが構造的にできない。
`STANDARD_AI_PROPOSABLE_CAPEX_TYPES` への `freezingPackagingExpansion` 追加、
または binding capacity 定義の修正が必要 = #05 の変更。加えて同時 3 案件枠（#04）が
新工場 2 件を並行させる余地を奪う |
| **50,000** | **C** | 45,000 の要件に加え、新工場 2 棟（44.0M）と Worker +7,215 人（現在の 63% 増）。
Worker 増は `laborUtilizationRate = 1.00` が続く現状では採用速度の制約を受ける。
Engine 側（同時案件枠・工場テンプレート能力配分）の変更なしには 32Turn 内で到達しない |
| — | **D 該当なし** | 50,000 でも粗利貢献は正（+45.7M/Q）、回収 1.0Q、運転資本増 113.5M に対し現金 388M。
**経済的に成立しない規模は 32〜50kt の範囲には無い** |

### H-4. Vision との整合について（判断は #05 に委ねる）

VAP の Vision は `targetScaleTonsPerQuarterAtQ32: 17,000`・`growthAmbition: "LOW"`・
「大きさでは勝たない」「量を追うための工場は建てない」である。
一方、DS3 では `scaleMultiplier 2.9` により実効 Q32 目標が 49,300 になり、
実測でも 30,636 t/Q・工場 2 棟に達している。
**Vision の記述と DS3 上の実効挙動は既に乖離している。**

本 PRE-AUDIT では VAP Vision を変更していない（指示どおり）。
32〜50kt という評価レンジを追うのであれば、
「VAP は量を追わない」という longTermNarrative 自体を改めるか、
DS3 の `scaleMultiplier 2.9` を見直すかのいずれかが必要であり、
これは **Stop Condition として #05 の判断を仰ぐ**。
