# ShrimpX V2 — 財務モジュール（Phase 8A: 原価計算・運転資本・財務三表基盤） アーキテクチャ v0.1

## 0. 本モジュールの位置づけ

`app/lib/v2/finance/` は、既存の市場価格・契約・原料・生産・品質・信頼・納期ロジック（Phase 1〜7B）が算出した事業実績データを**唯一の情報源**として、会社ごと・四半期ごとに原価・運転資本・PL/BS/CF・管理会計（固変分解・限界利益・損益分岐点）を生成する純粋関数群である。財務側で販売量・生産量・廃棄量・価格の**再計算は一切行わない**（抽出・金額換算・会計処理のみ）。

対象外（Phase 8Aでは扱わない）: 新規設備投資の意思決定、建設期間と稼働開始、新規借入・返済条件交渉・借換え、銀行信用スコア、借入限度額、増資・投資家選択、配当、為替、生成AI、財務ダッシュボードの本格UI、Redis/API実配線、本番ゲーム画面統合、complexityStressの修正、V1 Redis build問題の修正。

## 1. モジュール構成

- `types.ts` — USD金額型（`Usd`ブランド型、NaN/Infinity拒否・負数許容/禁止の区別）、コスト特性（variable/fixed/mixed/stepFixed）・コストドライバー・コスト記録、完成品原価台帳、売掛/買掛、財務状態、PL/BS/CF、品質損失内訳、原価内訳、限界利益レポート、全部/変動原価利益差異調整、四半期財務結果。
- `money.ts` — 金額換算の唯一の正規経路。**価格はUSD/HOSO換算kg・数量はHOSO換算トンのため、×1,000（`KG_PER_HOSO_EQ_TON`）を`amountFromTonsAndUnitPrice`等の共通関数で明示**し、桁誤りを構造的に防ぐ。表示用のUSD百万換算（`usdToMillions`）は表示層のみで使用し、内部計算では丸めない。
- `parameters.ts` — `FINANCE_PARAMETERS_V1`。賃率・加工費関連・工場固定費・販管費・回収/支払サイト・利率・税率・減価償却率・格落ち値引率をすべて1ファイルへ集約（暫定値・要校正）。
- `initialState.ts` — 5社の初期財務状態。原料在庫の初期金額は各社の初期原料ロット（実データ）のΣ(残数量×取得単価×1,000)から算出し、**利益剰余金を残差として決定することで開始時点の貸借一致（資産=負債+純資産）を構造的に保証**する。初期売掛金（前四半期販売分、開始四半期に回収）を持たせ、「売上は翌期回収・費用は当期支払」の片側だけが1四半期目に発生する非現実的なコールドスタート資金流出を回避する（継続企業の前提）。
- `quarterClose.ts` — 四半期決算の本体（`closeFinancialQuarter`）。前期財務状態＋当期事業実績→当期財務結果＋次期財務状態。
- `companyLabAdapter.ts` — 会社ラボの1四半期処理が持つ実績データから決算入力（`CompanyQuarterBusinessActuals`）を抽出するアダプター。抽出・フィルタ・金額換算のみを行う。
- 会社ラボ接続: `companyLab/runner.ts`の`advanceCompanyLabQuarter`末尾で5社ぶんの決算を実行し、`CompanyQuarterRecord.financialResults`へ保存、`CompanyLabState.financeState`で次期へ繰り越す。財務は既存の事業計算へ一切影響しない読み取り専用の追加である（統合テストFI-13で検証）。

## 2. 会計方針（採用した認識時点）

- **売上**: 契約締結時ではなく、当期の契約履行時に認識する。金額は履行数量×**成約時の契約単価**×1,000。契約後の原料価格変動で契約単価を変更しない（契約実績の`unitPrice`をそのまま使用。統合テストFI-4で成約時単価との厳密一致を検証）。
- **売掛金**: 売上認識時に市場別に計上し、回収サイト（全市場共通1四半期、暫定）に従って翌四半期に現金化。各債権は発生元・金額・発生期・予定決済期を保持する。
- **原料仕入**: 原料ロット取得時に在庫計上。国内買付は当四半期に現金払い（ベトナムの農家への即金性の高い支払実務を反映、支払サイト0）、輸入は**発注時**（=着地価格が確定し原料ロット`status="inTransitImport"`が生成される時点）に**買掛金と原料在庫（未着・輸送中区分）を同時に計上**し、1四半期後に現金決済する（相手勘定は常に買掛金`importRawMaterial`。物理的に未到着でも、既に取得原価が確定し会社の資産として存在するとみなす簡略化。現金は決済時のみ動くため、発注時点でキャッシュアウトは発生しない）。輸送中ロットはproduction側で`status="available"`のみを消費対象とするため、到着前に生産投入されることはない（財務側の在庫計上と生産側の使用可否判定は独立して整合している）。養殖は簡略化として収穫時（ロットが使用可能になった時点）に一括で現金認識する（育成期間中の飼料等の前払の期間按分はPhase 8B以降の精緻化候補として明示的に申し送る。養殖中ロットはBSの在庫に含めない）。
- **原料費**: 生産投入時に完成品原価へ振替（ロット別実取得原価ベース）。
- **完成品**: 生産時に原料費・加工費・労務費・製造間接費（全部原価計算では固定製造費配賦を含む）で在庫計上。
- **売上原価**: 完成品を契約履行に使用した時点で認識。未販売完成品は期末棚卸資産としてBSに残る（単体テストQ-5で「未販売分が売上原価へ流出しない」ことを検証）。
- **廃棄**: 廃棄数量分の**変動製造原価**を在庫に残さず当期の品質損失（廃棄損）として認識。固定製造費は良品（販売可能）数量にのみ配賦する（廃棄品への固定費配賦を行わない方針。会社全体の調整後生産量が0の場合は全額を未配賦固定費として当期費用化する＝生産が減っても固定費は消えない）。
- **再加工**: 数量を失わず、追加加工費（$200/トン、暫定）のみを当期原価へ加算。
- **格落ち**: 数量を失わず、販売時に「契約単価×値引率25%（暫定）」の売上控除として認識。
- **現金**: 直接法の現金台帳とCFが完全一致し、期首+増減=期末が厳密に成立する。**現金不足は勝手な資金注入で隠さず、負の現金残高＋`cashShortfall`フラグ＋不足額として明示的に記録する**（Phase 8Bの借入意思決定の入力になる）。負の現金には利息を付けない（`interestExpense`は既存の`shortTermLoans`/`longTermLoans`残高のみに基づき算出し、現金残高そのものには依存しないため、負の現金が既存借入と混同されることはない）。`financingCashFlow`はPhase 8Aでは常に0で、現金が負になっても自動的な借入・増資・資金注入は一切発生しない。**これはPhase 8Aの診断用の暫定処理（会社の資金繰り状態を可視化するための最小限の記録）であり、本番ゲームの資金調達ルールではない**。無利息・無制限の借入を許容しているわけではなく、Phase 8Bで銀行借入・信用限度・支払不能処理・緊急融資・投資・仕入制限を`cashShortfall`/`cashShortfallAmount`を入力として接続することを前提にした暫定状態である。
- **法人税**: 税引前利益が正の場合のみ税率20%（ベトナムCIT、暫定）で当四半期に現金納付（簡略化）。繰越欠損金はPhase 8Bへ申し送る。
- **支払利息**: 既存借入（短期2.2%/長期1.8%、四半期利率、暫定）に対する簡易利息。当四半期に現金払い。新規借入・返済はPhase 8B。
- **減価償却**: 固定資産取得原価に対する定額法（2.5%/四半期＝年10%相当）。非現金費用としてCFOで加算調整される。

## 3. 在庫評価方法（ロット別実際原価法＝FIFO系）と選択理由

**ロット別実際原価法**を採用する。理由: 既存のデータ構造がすでに（1）原料ロット（`RawMaterialLot.unitCost`＝ロット別取得単価、FIFO消費）、（2）完成品ロット（`FinishedGoodsLot`＝バッチ1:1生成、`sourceRawMaterialLots`で消費原料の内訳保持、FIFO消費）というロット単位の実際原価・FIFO消費構造を持っており、これと同一の粒度で原価を追跡するのが唯一の整合的な方法だから。移動平均法を重ねると既存のFIFO消費順序と評価が乖離する。恣意的な方式の混在はない（原料・完成品ともロット別実際原価）。

- **原料在庫のBS金額** = Σ(status available/inTransitImportのロットの残数量×取得単価×1,000)。実ロットが唯一の真実で、帳簿側に独立残高を持たない（乖離が構造的に生じない）。
- **完成品在庫**は`finance`側の**完成品原価台帳**（`FinishedGoodsCostLedgerEntry`）で管理する。数量の真実は常にproduction側の実ロットにあり、台帳は「ロット別の単位原価（変動費/固定費分離の8要素内訳）」だけを追加保持する。毎四半期、台帳残数量を実ロット残数量と照合・同期し、消費記録で説明できない減少（期限切れ等）は在庫廃棄損として当期認識する（説明できない増加はエラーとして拒否）。
- **COGSの原価流出は、契約充当消費の適用前後の実ロット残数量の差分（＝生産モジュールのFIFO消費の真実）に基づいて認識する**。`fulfillmentPlan.usage`のロット割付は計画時点のもので、期限切れ処理・会社×商品単位の集約FIFO消費により実消費とロット単位でずれうるため、収益・市場帰属・格落ち按分にのみ使う（実装中にこのずれによる台帳乖離を実際に検出し、この方式へ是正した）。

## 4. 原価計算と配賦規則

当期発生製造費を以下へ分離する（`ManufacturingCostBreakdown`）: 国内原料費・輸入原料費・養殖原料費（バッチの消費ロット別実取得原価を調達源泉で分類）、直接労務費（正社員）、臨時ワーカー費、残業費（正社員給与×適用残業率×割増1.5）、HOSO加工費（$350/トン基準）、PD追加加工費（+$170/トン）、VAP追加加工費（+$430/トン）、工場固定費、工場ユーティリティ（混合費: 固定$250k/工場＋変動$25/トン）、減価償却費、再加工費。加工費単価は`production/parameters.ts`の既存値を注入して使う（情報源を重複定義しない）。

配賦規則（文書化）:

- 変動労務費・変動ユーティリティ費 → バッチの品質調整**前**数量（originalTons）比で配賦（作業量は廃棄前の生産量に対応）。
- 固定製造費（正社員労務・工場固定費・固定ユーティリティ・減価償却）→ バッチの品質調整**後**数量（adjustedTons）比で配賦し、販売可能数量にのみ吸収（absorption）。会社全体の調整後数量0なら全額未配賦→当期費用。
- HOSO/PD/VAPの物理歩留まりは財務数量へ再導入しない。すべてHOSO換算数量で原価配賦する。

## 5. 品質損失の財務処理（Phase 7A保存済み実績の使用、二重計上禁止）

Phase 7Aの`BatchQualityAdjustment`（格落ち量・再加工量・廃棄量・重大事故・販売可能数量）をそのまま使用する。廃棄=変動製造原価ベースで当期損失（在庫に残さない）、再加工=追加費用のみ（数量損失にしない）、格落ち=販売時の売上控除（数量損失にしない）、重大事故=それ自体を架空の数量損失として別途加算しない（Phase 7Aが既に廃棄量へ反映済みの実績数量のみ使用）。同じ損失の製造原価・売上原価・品質損失への重複計上がないことは、売上原価合計=構成要素の和のテスト（Q-8）と利益差異調整の恒等式（F-11/12）で検証している。

**格落ちの按分方法と限界**: 格落ち品がどの契約履行へ使われたかは現行データから一意に追跡できないため、計画時点のロット割付（`fulfillmentPlan.usage`）×そのロットの格落ち率（Phase 7Aが`FinishedGoodsLotQualityInfo.downgradeRatio`としてロット別に保存済み）で按分する。ロット別格落ち率を使うため会社×商品×四半期の平均按分より精密だが、「同一ロット内のどの部分が格落ち品か」までは特定できない（限界）。

## 6. 運転資本

暫定パラメータ（`workingCapital`）: 売掛金回収サイト=全市場共通1四半期、輸入買掛金支払サイト=1四半期、国内原料支払サイト=0（即金）。四半期単位のゲームのため、日数ではなく決済四半期数へ決定論的に変換して保持する。売掛金・買掛金レコードは発生元（sourceRef）・金額・発生期・予定決済期を持ち、予定期到来分だけが現金化される（テストQ-9）。延滞・未回収（貸倒）はPhase 8Aでは発生しない（全額予定どおり回収・支払。信用リスクはPhase 8B以降の課題として明示）。

## 7. PL / BS / CF の構造

- **PL（全部原価計算）**: 売上高 → 格落ち・品質関連売上控除 → 純売上高 → 売上原価（原料費・加工費・人件費・工場固定費〔固定ユーティリティ・減価償却の配賦含む〕・再加工費・廃棄損・未配賦固定製造費）→ 売上総利益 → 販管費（営業/調達人件費・一般管理固定費・変動販売物流費）→ 営業利益 → 支払利息 → 税引前利益 → 法人税 → 当期純利益。
- **BS**: 現金（負数許容＝明示的資金不足）/売掛金/原料在庫/完成品在庫/その他流動資産/固定資産純額 — 買掛金/短期借入金/長期借入金/その他負債 — 資本金/利益剰余金。毎四半期`balanceDifference`≈0を検証（許容誤差$0.01）。
- **CF**: **直接法を主表**として採用（現金台帳と構造的に一致し、期首+増減=期末が厳密に成立するため）。営業CFの内訳は顧客回収・原料支払・製造費支払・販管費支払・利息・税。CFI・CFF はPhase 8Aでは0（新規投資・新規借入なし）。補助内訳として**間接法照合**（純利益+減価償却−ΔAR+ΔAP−Δ在庫）を生成し、直接法CFOとの一致を毎四半期検証する（`directIndirectDifference`≈0）。利益剰余金は純利益でロールフォワードし、一致をテストで検証（Q-13/FI-3）。

## 8. 固変分解・限界利益管理（Phase 8A追加要件）

- **コスト記録（`CostRecord`）**: 全主要費用（約20記録/会社/四半期）へ勘定科目・コスト特性（variable/fixed/mixed/stepFixed）・固定部分・変動部分・コストドライバー・ドライバー数量/単価・商品/市場/工場（可能な範囲）・発生四半期・短期削減可能性・発生元実績データ（sourceRef）を付与。混合費（工場ユーティリティ）は固定部分と変動部分を分離保存し、合計から再推定しない。ドライバーは実装指示の列挙を文字列unionで定義済みで、後から追加可能。
- **段階固定費**: 正社員給与（ドライバー=正社員数）・工場固定費（ドライバー=工場数）・営業/調達人件費をstepFixedとし、生産量が減っても自動削減されない（テストF-10）。能力増設・工場閉鎖による段階変化はPhase 8Bで接続する。
- **限界利益レポート（変動原価計算）**: 売上高→売上控除→純売上高→変動原料費・変動加工費・変動労務費・変動品質費（再加工+廃棄損の変動費相当）・変動販売費→限界利益（率）→固定製造費・固定人件費・固定販管費→管理会計上の営業利益→損益分岐点売上高（固定費÷限界利益率）→安全余裕額/率→経営レバレッジ。損益分岐点の前提商品構成（純売上高構成比）を結果へ保存する。
- **商品別・市場別限界利益**: 商品別は実消費原価で厳密に帰属。市場別は「商品別の実消費平均変動単価×市場×商品の履行数量」で按分（実消費のロット→市場対応が存在しないため。按分と明記）。共通固定費は商品/市場へ配賦せず`commonFixedCost`として別掲（直接固定費はPhase 8Aでは0、構造のみ保持）。商品へ帰属できない共通変動費（原料期限切れ廃棄損等）は`commonVariableCost`として別掲し、Σ(商品別限界利益)=全社限界利益+commonVariableCostの恒等式を維持する（テストF-14）。
- **全部/変動原価の利益差異調整**: 期首在庫中固定製造費→当期配賦→販売払出→廃棄払出→期末在庫中固定製造費のフローを保存し、**営業利益差額=期末在庫中固定製造費−期首在庫中固定製造費**が毎四半期厳密に成立する（単体F-11/12・統合FI-11）。

## 9. 永続化（schemaVersion 4）

`PersistedGameStateV2`へ`financeStates`（`CompanyFinanceState[]`）を追加し、`CURRENT_PERSISTED_GAME_STATE_VERSION`を4へ上げた。v1/v2/v3データ（キー自体が存在しない）はdecode時に空配列＝財務状態未初期化を補い、利用側が必要時に`buildInitialCompanyFinanceState`で整合する初期財務状態を構築する（キーの有無で判定する追加的変更、マイグレーション不要）。検証はNaN/Infinity拒否、負数禁止残高（売掛/買掛/在庫/借入/資本金）の拒否、減価償却累計額≦取得原価、格落ち率0〜1等（負の現金・負の利益剰余金は明示的な状態として許容・復元可能）。companyLab→Redis/APIへの実配線は行っていない（対象外）。

## 10. 会社ラボへの接続とCLI

`advanceCompanyLabQuarter`が各四半期末に5社の決算を実行し、`CompanyQuarterRecord.financialResults`へ全内訳（PL/BS/CF/原価内訳/品質損失/コスト記録/限界利益/利益差異調整）を保存する。8/32ターン一括実行に対応。CLI（`npm run v2:company-simulate`）のsummary形式へ売上高・営業利益・純利益・営業CF・期末現金・総資産・純資産と資金不足/債務超過フラグの2行を追加した。JSON出力は`financialResults`を含む全内訳を取得可能（CSVの列構成は変更していない）。
