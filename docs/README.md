# ベトナムエビ輸出事業ゲーム 仕様書

最終更新: 2026-07-15

このディレクトリは、`vietnam-shrimp-game`リポジトリのゲーム仕様を、AI・人間を問わず今後の実装・修正担当者が安全に作業できるよう整理したものです。**すべての記載はコード・README・UI文言から直接確認できた内容に基づき、確認できない事項は「TODO」「要確認」「未実装」のいずれかで明記しています。** 「本来あるべき仕様」を推測して確定事項のように書いた箇所はありません。

## 重要な前提：ブランチによる実装差

本リポジトリには2026-07-15時点で以下の2ブランチが存在し、実装範囲が異なります。

- **`main`**：ゲームセッション管理・GMコンソール・意思決定フォームの保存まで。ターン処理（決算計算）は未実装。
- **`claude/turn-processing-engine`**（未マージ、PRなし）：`main`に加えてターン処理エンジン、結果表示、GM管理画面、プレイヤー画面への実データ反映を追加。

各ドキュメントには、記載内容がどちらのブランチのものかを明記しています。作業前に自分がどちらのブランチを見ているか確認してください。詳細は`system_architecture.md`を参照。

## 各仕様書の役割

| ファイル | 役割 |
|---|---|
| `README.md`（本書） | 仕様書全体の案内、更新ルール |
| `game_manual.md` | ゲームの目的・遊び方・進行フロー・フェーズ0〜6・GMの役割・勝敗条件 |
| `parameter_spec.md` | 全パラメータの型・単位・初期値・上限下限・保存場所・計算式・画面表示位置の一覧 |
| `event_spec.md` | イベント（市場変動・災害等）の仕様。現状は全項目未実装 |
| `ai_company_spec.md` | AI担当会社（ai-a/ai-b/ai-c）の仕様。現状は選択UIのみで自動意思決定ロジックは未実装 |
| `finance_spec.md` | 売上・原価・金利・BS更新・信用スコア等の計算式（コードからそのまま数式化） |
| `system_architecture.md` | Next.jsの構成、ページ・API一覧、Redisデータ設計、環境変数、ターン処理のデータフロー |
| `implementation_status.md` | 機能ごとの実装状況一覧表 |
| `decision_log.md` | 今後の仕様変更を記録するテンプレート |

## どの資料を最初に読むべきか

1. **`system_architecture.md`**（特に冒頭の「ブランチによる実装差」）— 自分が見ているコードがどの範囲を指すか把握するため、最初に読む
2. **`implementation_status.md`** — 何が実装済み・未実装かを俯瞰する
3. 作業目的に応じて以下を参照：
   - ゲームルールを理解したい → `game_manual.md`
   - 特定のパラメータの型・保存場所・計算式を調べたい → `parameter_spec.md`（詳細計算式は`finance_spec.md`）
   - 財務計算ロジックを変更したい → `finance_spec.md`
   - イベント機能を新規実装したい → `event_spec.md`
   - AI意思決定を実装したい → `ai_company_spec.md`
4. 仕様変更を行った場合は最後に **`decision_log.md`** に記録する

## 仕様変更時に更新すべきファイル

仕様・コードを変更した場合、変更内容に応じて以下を更新してください。1つの変更が複数ファイルに影響することがあります。

| 変更内容 | 更新すべきファイル |
|---|---|
| ゲーム進行フロー、フェーズの追加・変更 | `game_manual.md`, `implementation_status.md` |
| パラメータの追加・変更（型・単位・初期値・上限下限） | `parameter_spec.md` |
| 財務計算式の変更 | `finance_spec.md`, `parameter_spec.md`（関係する計算式の欄） |
| イベント機能の実装 | `event_spec.md`, `implementation_status.md` |
| AI意思決定ロジックの実装 | `ai_company_spec.md`, `implementation_status.md` |
| ページ・API・Redisキー構造の変更 | `system_architecture.md` |
| いずれの変更でも | `implementation_status.md`（該当行の状態更新）, `decision_log.md`（変更の記録） |

## 仕様書とコードが矛盾した場合のルール

**仕様書とコードが矛盾する場合、コードが正であるとみなして直接判断せず、まず矛盾箇所を明示した上で人間に確認すること。** 具体的には：

1. 矛盾を発見した時点で、該当する仕様書に「コードとの不一致（要確認）」として記録する（本仕様書群では既にいくつかの不一致を記載済み。例：`game_manual.md`のフェーズ0の記述、`parameter_spec.md` §6の「価格」入力の不一致）
2. 不一致を解消する変更（コード修正か仕様書修正か）を、確認なしに一方的に行わない
3. 解消した場合は`decision_log.md`にその経緯を記録する

## 記載ルールの原則（本仕様書群全体に共通）

- 確定仕様・現在の実装・設計案・未実装・TODO・コードとの不一致・確認が必要な事項を区別して記載する
- 「本来あるべき仕様」と「現在のコードの動作」を混同しない
- コードに存在しない数式・パラメータを新たに作らない
- 秘密情報・トークン・APIキー・パスワードは記載しない
