## 4. 市場別絶対需要が観測不能な理由の分類（Phase F-4）

コードを直接調査した結果、次の4区分のうち **(b)** であることを確認した。

- (a) 市場エンジンが絶対需要を一切計算していない → **該当しない**。`market/globalDemand.ts`の`calculateWorldDemand(demandMarkets)`は、実際に市場別の絶対需要`byMarket: Record<DemandMarketId, HosoEqTons>`を内部で計算している（`market/index.ts`の`calculateMarketQuarter`内、42行目 `const worldDemand = calculateWorldDemand(input.demandMarkets);`）。
- **(b) 市場エンジンは計算しているが、公開出力（`MarketQuarterResult`）へ含めていない → 該当する。** `calculateMarketQuarter`は`worldDemand.byMarket`を一度も参照・返却せず、`worldDemand.totalWorldDemand`由来の集計値のみを`MarketQuarterResult.worldDemand`（世界合計、市場別ではない）として返す。市場別の内訳はこの時点で捨てられている。
- (c) 公開UIには市場別需要があるがStandard AIへ渡っていない → 該当しない（そもそも(b)の時点でエンジン出力自体に無いため、UI層の話ではない）。
- (d) 会社固有の需要上限のみが欠落 → 該当しない（会社別・市場別のいずれの絶対需要も欠落している）。

**#04確認事項**: `market/globalDemand.ts`の`byMarket`をそのまま`MarketQuarterResult`へ追加で返すよう変更すれば（既存の計算をそのまま公開するだけで、需要式自体は1文字も変えない）、市場別絶対需要の公開情報化は技術的には低リスクで可能である。ただし本ラウンドは「market-demand-engine changes」が禁止されているため、この変更は今回実施していない（次回接続候補として#17へ記載）。

**Shadow engineが実際に最適化している対象（数式レベル）**: 上記の欠落により、Shadow Sales Allocation Engineが尊重する唯一のceilingは、市場別需要ではなく **会社全体の`desiredByProduct`**（`decision/sales.ts`が計算する商品別理論上限。同ファイル内で「診断専用・理論値」と既に明記）である。市場ごとの配分は、`desiredByProduct`という単一の company-wide ceilingを、各市場の営業容量関数`capacity(h)`の**限界効果容量**（次の1人を割いたときの増分）で比較して、貪欲法（1人ずつ）で決定する。したがって最終的な配分は「(1) 会社全体の商品別ceiling」「(2) 各市場の営業人員飽和特性」「(3, contribution-orientedのみ) 商品別CM$/effort係数」の3つだけで決まり、市場別の需要規模・供給者シェア上限・CTSは一切参照していない（参照できない。観測に存在しないため）。今回の38人分析で全市場が「HEADCOUNT_BUDGET_EXHAUSTED」になったのは、この構造の直接の結果である。
