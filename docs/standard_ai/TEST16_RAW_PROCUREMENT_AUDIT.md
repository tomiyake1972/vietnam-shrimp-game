## 0. 結論（先に）

**HOSO capex が発動しない原因は原料ではなかった。**

原料を無制限に与えて `rawMaterialShortfall` を全社ゼロにしても、
**設備投資は8Q通して一度も提案されない**（提案0件 / 55件すべて CAPEX_DEFERRED）。

真因は段階Cの能力設定そのものにある。

```
設備稼働率 = 実生産量 / commonProcessing能力   （production/loadMetrics.ts:54）
```

分母は **common 単独**である。段階Cで common を全社30,000tに統一した一方、
商品別能力の合計は19,000〜22,000tしかない。したがって

```
理論上の最大稼働率 = Σ商品別能力 / common
```

| 会社 | Σ商品別 | common | 理論上限 | 原料十分ケースの実測最大 |
|---|---|---|---|---|
| BAL | 20,000 | 30,000 | **0.667** | 0.667（＝理論上限に到達） |
| MASS | 22,000 | 30,000 | **0.733** | 0.729 |
| JPQ | 21,000 | 30,000 | **0.700** | — |
| VAP | 20,000 | 30,000 | **0.667** | 0.619 |
| CONSV | 19,000 | 30,000 | **0.633** | 0.590 |

capex の持続性しきい値は **0.92**（`capexSustainedUtilizationThreshold`）。
どの会社も、**全設備をフル稼働させても算術的に到達できない。**

Phase 1監査 §2-3 で「商品別能力の合計 > 共通能力」という構造が既に成立していると
記録した（BAL 24,000 > 22,000 等）。**段階Cはこの大小関係を反転させてしまった。**
これが capex 経路を閉じた直接原因である。

## 1. raw shortage の主因

**国内調達の資金ゲート。市場側の供給ではない。**

40行（5社×8Q）中：

| 状態 | 行数 |
|---|---|
| 資金制約が掛かった（`procurementScaleRatio` < 1） | **35** |
| 市場配分で買い負けた | **0** |
| 反独占シェア上限に当たった | **0** |
| 価格を理由に買わなかった | **0** |
| 資金制約が無くても意向が所要に届かない | 13（うちT1/T2が10） |

**配分 = 希望量 × `procurementScaleRatio` が40行すべてで厳密に一致した。**
つまり国内市場は一度も会社を配給制限していない。会社は「資金が許した量」を
100%取得できている。

`scaleRatio` は 0.33〜0.90（MASSは2回 0.000）。

### 誤検知だった指標について

当初 `unallocatedSupply = 0` を「市場の枯渇」と読んだが、これは誤りだった。
プレイヤー系会社が配分対象にできる供給は

```
companyAvailableDomesticSupply = 取引成立量 × min(1, 全社買付意向 / 実効需要)
```

として**全社の意向に比例して決まる**（`turn/runner.ts:124-130`）。
残余供給は構造上ほぼ常に0になり、供給不足を意味しない。
判定ロジックを「配分 < 資金制約後の希望量」へ修正した。

### 2.1 意向そのものはT3以降おおむね妥当

| MASS | 0.72 | 0.93 | 1.03 | 1.05 | 1.01 | 0.73 | 0.93 | 0.69 |

T1/T2 が低いのは **輸入リードタイム2四半期**（`standardLeadTimeTurns = 2`）が原因で、
T1・T2の輸入到着が全社ゼロだから。構造上の立ち上がりであり、判断の誤りではない。

### 2.2 **借入判断が調達必要額と接続されていない（重大）**

`standardAi/decision/finance.ts:33`:

```ts
const desiredAmountUsd = cashUsd < targetMinimumCashUsd ? targetMinimumCashUsd - cashUsd : 0;
```

**AIは「最低現金バッファを割ったとき」しか借りない。調達必要額は借入判断の入力ですらない。**

その結果：

```
未充足なのに借入申請ゼロ、かつ借入余力が残っていた行: 17 / 40
うち、余力だけで未充足額を全額賄えた行:              14
```

具体例（いずれも「申請なし」）:

| | 調達未充足額 | 未使用の借入余力 |
|---|---|---|
| CONSV T3 | 13M USD | **30M USD** |
| CONSV T5 | 8M | **36M** |
| CONSV T7 | 3M | **45M** |
| JPQ T7 | 13M | 25M |
| JPQ T8 | 7M | 28M |
| VAP T7 | 11M | 15M |

CONSVは8Qを通じて一度も借入を申請せず（T2の1回を除く）、
毎期30〜47M USDの余力を遊ばせたまま原料を買い負けている。

**これは Standard AI の判断の欠落であり、ゲームバランスの問題ではない。**

### 2.3 価格による調達判断は存在しない

`decision/procurement.ts:110` は `priceAdjustmentUsdPerHosoEqKg` を**常に0**で出す。
実測でも提示価格 − 市場価格 = 0.0000 が40行すべて。

したがって「価格が高いので買わない」という判断は**現在のStandard AIには存在しない**。
4分類のうちこの1つは、現行実装では原理的に発生しない。

## 4. cash / debt 制約

### 4.1 資金ゲートの式

`financing/liquidityClose.ts:349-355`:

```
利用可能流動性 = max(0, 前期末現金) × domesticPurchaseCashAllocationRatio + 承認融資
scaleRatio     = clamp(利用可能流動性 / 調達必要額, 0, 1)
```

`domesticPurchaseCashAllocationRatio = 0.6`（`financing/parameters.ts:157`）。
**現金が潤沢でも、その60%までしか原料に回せない。**

資金制約が掛かった35行のうち、**この比率を1.0にするだけで解消する行が12**。
残り23行は借入が必要（そして§2.2のとおり多くは余力がある）。

### 4.2 MASSだけは本当に借りられない

MASSは毎期 `borrowingAvailableCapacity = 0`、binding は `collateralBased`。

MASSは §2.2 の「借りられるのに借りない」ではなく、**本当に与信が尽きている**。
段階Cで能力を12,000tへ再設計した判断2の帰結を追跡する対象としてここに記録する。

## 5. HOSO capex が閉じる因果（確定）

```
段階C: common 30,000 統一 ＆ Σ商品別 19,000〜22,000
  ↓
設備稼働率 = 実生産量 / common の理論上限が 0.633〜0.733 に固定
  ↓
capex の持続性条件（前期稼働率 >= 0.92）が算術的に到達不可能
  ↓
商品別ボトルネックは正しく検知される（shortfallRatio 1.05〜1.35、86件）
が、sustained が一度も成立しない
  ↓
CAPEX_DEFERRED × 92件、提案 0 件、8Q固定
```

原料不足はこの連鎖を**悪化させていたが、原因ではなかった**（§6）。

なお `capexSustainedUtilizationThreshold` は Standard AI の判断ロジックであり、
今回のご指示範囲（ゲームバランス）に含まれないため**変更していない**。

| 商品別ボトルネック検知 | 86件 | 42件（shortfallRatio 1.05〜1.35） |

| **capex 提案** | **0件** | **0件** |
| HOSO能力の推移 | 変化なし | **変化なし（8,000tのまま。12k→16k→20k→24kへ進まない）** |

**原料をゼロ制約にしても、稼働率は理論上限（0.59〜0.73）に張り付くだけで

### このプローブの限界（正直に記載）

原料を対価なしで積み増しているため、**損益・現金の数値は信頼できない**

実際、営業利益は全社マイナスに転じるが、これは会計上の歪みであって
経済的な発見ではない。

**このプローブから読み取ってよいのは、数量・稼働率・capex発動の有無だけである。**
集中生産効果の観測は Stage E 未実装のため今回は確認できていない。

## 7. 判断をお願いしたい点

原因が原料ではなく**能力設定の構造**だったため、当初想定していた
「原料調達側のゲームバランスを直す」では解決しない。

### (A) 最優先 — common と商品別能力の大小関係

段階C以前は `Σ商品別 > common` だったものを、段階Cで反転させた。
これを戻さない限り、**どのcapexパラメータをどう変えても投資は発動しない。**

- **(A-1) 推奨**: common を Σ商品別より小さい水準へ下げる（例: 全社18,000t）。
  Phase 1で確認した「commonが実質的な総量上限」という設計へ戻る。
  指示C3の構造とも整合する。
- (A-2) 商品別能力を引き上げて Σ > common にする。ただし
  「序盤から能力が余る」という段階Cの問題が戻る。
- (A-3) common を能力制約ではなく別の役割に位置づけ直す。

### (B) Standard AI の借入判断（§2.2）

調達必要額が借入判断の入力になっていない。17/40行で余力を遊ばせている。
これは**バランスではなく判断ロジックの欠落**なので、
今回の変更禁止範囲に触れます。修正してよいかご指示ください。

### (C) `domesticPurchaseCashAllocationRatio = 0.6`（§4.1）

これ単独で12行の資金制約が解消する。現金が潤沢でも60%しか原料に回せない
という制限が意図どおりかご確認ください。

### (D) MASSの与信枯渇（§4.2）

段階Cの能力再設計（判断2）の追跡対象。T6・T8で原料調達がゼロになっている。
