## 2. 「-$2.0M」問題の再分類（三宅さんの質問への回答）

Round 2で報告した「headroom -$2.0M」は、本再現ケースの実測値と人間案スケールをやや異なる前提（Round 2は生産規模を単純な10,000t等スケールシナリオの延長で当てはめていた）で組み合わせた**イラストレーティブな概算**だった。今回、Phase F-7で正確な人間案の生産・調達内訳（HOSO 9,100/PD 4,500/VAP 1,850、国内調達14,300t）を当てはめて再計算した結果は次の通り、3つの分類のうち明確に **(b)** である。

- (a) 当期予想現金そのものがマイナス（cash<0） → **該当しない**。財務調達前の当期予想現金は+$33.75M（capex込みでも+$25.95M）と、いずれも正の値である。
- **(b) 目標最低現金バッファ（$34.66M）に対して不足している → 該当する。** Capexを含めなくても、headroomは既に-$0.92Mであり、わずかにバッファを下回っている。
- (c) Capexを含めた場合にのみ不足が生じる → **部分的に該当**。Capex無しでもわずかに不足するが、Capexを含めるとさらに-$8.72Mへ悪化する。「Capexを実施するかどうか」が、わずかな不足（-$0.92M）を、より明確な不足（-$8.72M）へ変えるという意味で、Capex判断の重みは大きい。

**結論**: 現金そのものが尽きるわけではないが、目標最低現金バッファという安全余裕の観点では、人間案スケールの生産・調達・労務・SGAだけで既にわずかに不足しており、Capexを実施すればその不足はさらに拡大する。これは「借入で埋め合わせが可能かどうか」の判断（Phase F-9）に直結する。

**確認事項**: このケースでは、Turn1で発生したAR（全5市場、合計$41.64M）は**全額がTurn2で決済期日を迎え、全額が当期の確実な現金化として計上される**（`receivablesNotYetDueUsd=0`）。これは既存の回収サイトルール（`arCollectionQuarters=1`）が正しく反映された結果であり、帳簿上のAR全額を無条件で「使える現金」とみなしているわけではない（単体テストでも、`receivablesNotYetDueUsd>0`のケースでは`projectedCashBeforeFinancingUsd`が必ずAR全額加算より小さくなることを構造的に確認済み）。実際のTest14（38人規模・$44.9M）でも、同じ1四半期ラグの回収ルールが適用されているはずであり、Turn1起源のAR全額がTurn2で現金化される（Turn3以降へ持ち越されるAR残高は存在しない）と推定される。ただし、これは本再現ケースの構造から**推定**したものであり、実際の38人ケースのAR台帳を直接確認したものではない点は明示しておく。
