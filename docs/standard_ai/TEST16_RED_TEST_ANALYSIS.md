## 485 自社養殖の池入れ量は調達制約スケール比率どおりに縮小する → **修正済み（fixture依存）**

| | |
|---|---|
| **守る因果** | `constrainedAquacultureStocking = planned × scaleRatio`。池入れ量が資金制約の比率どおりに縮小すること |
| **何が変わったか** | 中間ケースの現金額 22,000,000 がハードコードされていた。利用可能流動性 = 現金 × 比率 なので、0.6では 13.2M（部分制約）だったが 1.0 では 22M となり調達必要額を満たして scaleRatio が 1.0 に張り付いた |
| **fixture依存か** | **はい。** 22M という値が比率0.6専用だった |
| **正当な変化か** | はい。因果自体（縮小比率＝scaleRatio）は無傷 |
| **回帰か** | いいえ |

**対応**: 現金額を資金ゲートの式から逆算するようにした。

```ts
const partialCashUsd = (plannedCashNeedUsd * 0.5) / FINANCING_PARAMETERS_V1.liquidity.domesticPurchaseCashAllocationRatio;
```

比率をどう変えても「必要額の半分だけ賄える現金」になるため、今後この種の張り付きは起きない。

## 1535 SNAP-7 緊急融資 → **修正済み（命題そのものが誤っていた）**

| | |
|---|---|
| **守る因果** | 題名は「二重計上の否定」。旧実装は「緊急融資が発動したturnでは通常融資実行=0」と表現していた |
| **何が変わったか** | BAL 2016Q1 で通常融資 7.38M と緊急融資が併存した |
| **fixture依存か** | いいえ |
| **正当な変化か** | **はい。エンジンは併存を明示的に許している** |
| **回帰か** | **いいえ（分類の変化ではない）** |

### ご指示の確認事項「分類そのものが変わったのか」への回答

**分類は変わっていません。** `financing/liquidityClose.ts:583-586` は

```
// --- 緊急融資の判定（通常融資だけでは利息・必須元本を払いきれない場合の最後の手段） ---
const shortfallBeforeEmergency = max(0, 利息 + 約定元本 − 通常融資実行後の現金)
```

と、**通常融資を実行した後の残余**に対して緊急融資を判定する設計です。
「通常と緊急は同一四半期に併存しない」ことをエンジンは保証していません。
旧命題は、当時のデータでたまたま併存例が無かったことに依存していました。

短期運転資金の借入判断を入れた結果、「運転資金として通常融資を受けたうえで、
なお元利返済に足りず緊急融資も受ける」という**設計どおりの**組み合わせが現れました。

**対応**: 題名どおり「二重計上の否定」を検証する形へ命題を書き直した。

- 通常 + 緊急 = 合計実行額（同じ金額を二度数えていない）
- 緊急融資は当期の元利返済必要額を超えない（残余に対する額であり、重ねて実行していない）

## SAI-5因果(1b) の再設計

マクロ勝率（70セル中60%）を廃止し、**pairwise A/B** へ再設計した。

守る因果:
> 同一市場・同一商品・同一価格・同一品質・同一顧客関係・同一納期信頼性・同一営業人員のもとで、
> 営業基盤（salesBaseScore）だけを変えると、正式ロジック上の成約獲得力が期待方向へ動く

観測点は `sales/allocation.ts` の正式ロジックそのもの:

```
salesBaseContribution = competitivenessWeights.salesBase × (salesBaseScore / 100)
  → sumCompetitivenessContributions → 水位法配分
```

検証内容:
1. 営業基盤の寄与が高い方で大きい。**他の寄与項目は完全に一致**（営業基盤だけが差分）
2. 合成競争力ウェイトへ伝播している
3. 実際の配分量も高い方が多い

補題として「ウェイト0なら営業基盤の差は配分をビット単位で変えない」も追加した。

**参加社数について**: 1社あたりの成約上限は `対象需要 × maximumSupplierShare` であり、
2社だと双方が上限に張り付いて競争力の差が配分へ現れない。競争力による配分（水位法）が
実際に働くよう、中位の会社を1社加えて3社で競わせている。

「営業基盤がゲーム全体の成約結果を常に支配する」ことは要求していない。

**財務系3件（581 / 1063 / 1535）について、ご指示の「分類そのものが変わったのか」への回答は
いずれも「いいえ」です。** 通常融資・緊急融資・paymentDefault の判定ロジックは
一切変更しておらず、変わったのは各社の資金状態と現金の使われ方です。
したがって**回帰として止める必要はありません。**
