## 1. 借入可能額（Borrowing Capacity）観測ギャップの分類（Phase F-9）

`financing/borrowingCapacity.ts`の`computeBorrowingCapacity`を直接確認した。必要入力は次の7項目: 担保USD評価（`receivablesUsd`/`rawMaterialAvailableUsd`/`rawMaterialInTransitUsd`/`finishedGoodsUsd`）・直近EBITDA相当（`ebitdaLikeQuarterlyUsd`）・純資産（`totalEquityUsd`）・既存借入残高・信用区分（`creditTier`）・重大延滞フラグ・債務超過フラグ。

**結論**: 借入限度額の算出ロジック自体（担保・収益力・信用区分×自己資本の3系統からmin/maxを取る計算式）は**既に実装済み**であり、新しい財務ルールを作る必要はない。また、この関数の全入力（`planQuarterFinancing`が実際に使っている`prevFinanceState`・`prevFinancingState`・`priorQuarterResult`・`customerTrustAvg`・`deliveryReliabilityAvg`・`collateral`）は**いずれも前四半期末時点の確定値**であり、当期の意思決定に依存しない。したがって`StandardAiObservation`へ、これら7入力（信用スコア計算・EBITDA相当・担保USD評価・重大延滞/債務超過判定）を配線として追加する作業は、技術的には**純粋な配線タスク（wiring-only）**であり、新しい#04финансルールの設計は不要と判断する。

**今回実施しなかった理由**: 7入力を正しく配線するには、`ownState.financeState`の資産評価ロジック（`finance/creditScore.ts`相当の信用区分計算、EBITDA相当の算出方法の確認）を含む複数ファイルへの変更が必要であり、本ラウンドの残り時間・診断専用の原則を踏まえ、誤配線によるバグリスクを避けるため次回への持ち越しとした（借入意思決定そのものの実装は三宅さんの指示どおり今回一切行っていない）。**次回接続候補（#17）として明記する。**

## 4. 「営業force改善→生産がボトルネックになる」ダイナミクスの定量的説明

Phase F-2の分析（38人・実測headcount）で、Volume-shadow/Contribution-shadowはいずれも現在の6,584.8t（本番Current配分の実現販売）を9,960.8t（Volume）/8,432.3t（Contribution）まで伸ばせると示した。これを現在の生産能力と比較すると:

- 現在の実効生産能力の合計（HOSO+PD+VAP専用ライン単純合計）＝8,550+6,840+5,130＝20,520t/四半期。Volume-shadowの9,960.8tはこの合計の48.6%であり、単純合計だけを見れば生産能力に余裕があるように見える。
- しかし、HOSO専用ラインは既に人間案生産候補（9,100t）だけで実効容量（8,550t）を超過している。Shadow allocationが商品ミックスをどう変えるか（Volume-orientedはeffort係数最小の商品＝HOSOを優先しがちで、Contribution-orientedはPD/VAPへ寄る）によって、「営業force改善で増えた需要をどの商品で満たすか」が変わり、それによって生産側のどのライン（HOSO専用／PD専用／VAP専用／共通前処理／凍結包装）が先に頭打ちになるかが変わる。

**結論**: 営業force改善（人員配分の最適化）を先に進めると、遅かれ早かれ生産側のいずれかのラインが次のボトルネックになる可能性は高い（特にHOSO専用ラインは既に人間案規模ですら不足気味）。ただし「どのラインが」「いつ」ボトルネックになるかは、Shadow allocationがどちらの目的関数（Volume/Contribution）で動くか、および将来の生産計画側の商品ミックス判断（本ラウンド対象外）に依存するため、本診断だけでは一意に決まらない。次の生産capex判断（#17候補）では、共通前処理・凍結包装だけでなくHOSO専用ラインの増設余地も併せて確認すべきである。
