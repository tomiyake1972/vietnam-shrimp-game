## 3. **VAPDEV-INT-1 の原因確定（会計バグではない）**

### 事象
`vapProductDevelopmentSpendUsd: 250,000` を設定したとき、
期末現金の差分が 250,000 ではなく **200,000** になった。

### 原因

```
incomeTaxRate = 0.2  （finance/parameters.ts:169）
250,000 × (1 − 0.2) = 200,000   ← 観測値と完全一致
```

**法人税の節税効果である。** VAP開発投資はSG&Aとして費用計上されるため、
税引前利益が250,000減り、法人税が50,000減る。正味の現金減少は200,000になる。

### 追跡した項目

| 項目 | 結果 |
|---|---|
| 投資意思決定 | 250,000がそのまま渡っている。クランプ・階層丸めなし |
| capex支出 / CIP | 該当なし（capexではなくSG&A費用計上） |
| cash movement | SG&A +250,000 → 税引前利益 −250,000 → 法人税 −50,000 → 正味 −200,000 |
| 他の同時意思決定 | 影響なし。両ケースは decisionsBase を共有し差分は当該フィールドのみ |
| 能力変更による行動差 | **これが引き金**。段階CでBALがQ1から課税所得を持つようになった |

### 当期成約への遡及がないことも確認

`runner.ts:1659-1663` に明記があり、VAP開発スコアの更新は**次期**へ繰り越される。
当期の成約計算は前四半期末までの `productDevelopmentState` だけを使う。
投資が当期の売上を動かして差分を生んでいるのではない。

### 判定: 旧fixture依存

テストが守りたい「会計計上の唯一の情報源」という性質は正しく機能している。
ただし期待式が **「現金差分 = 投資額」** であり、これは
**その会社がその四半期に法人税を払っていない場合にのみ成立する**式だった。
段階C以前はBALのQ1が課税所得ゼロだったため偶然成立していた。

### 直し方の案（判断待ち）

**案a（推奨）**: 税効果を織り込んだ期待式にする。
`incomeTaxRate` は `FINANCE_PARAMETERS_V1` から読み、定数を直書きしない。
課税所得の有無で分岐する（`profitBeforeTax` の符号で判定）。
「投資額がSG&Aとして一度だけ計上され、税効果を通じて現金へ反映される」
という、より正確で強い性質を検証できる。

**案b**: 課税所得ゼロのケースを専用fixtureで作り、`現金差分 = 投資額` を維持する。
「税金が無い世界でだけ正しい」ことしか言えなくなるため非推奨。
