## 1. capex現金ゲート（判断 a-2 の実装）

### 実装した式

```
requiredCash = targetMinimumCash + 投資額 + 投資額 × capexCostSafetyRatio
```

### ご指示の式との差について（報告事項）

ご指示は

```
requiredCash = targetMinimumCash + capexCost × capexSafetyRatio
```

でしたが、これを字義どおりに実装すると **同じご指示の後半
「投資後に最低現金バッファを割る場合は引き続き見送ること」と矛盾します。**

HOSO増設は `paymentRatios = [1.0]` で 8M USD 全額が単一四半期に出るため、
`ratio = 0.25` なら必要現金は `targetMin + 2M` で足りてしまい、
投資直後の現金は `targetMin − 6M` とバッファを割り込みます。

そこで「バッファを割らないぶん（＝投資額そのもの）」と
「追加の安全余裕（＝投資額 × ratio）」を分けて足す形にしました。
これにより `capexCostSafetyRatio` は純粋に追加余裕を表し、
0.25 と 0.50 の比較も意味を持ちます。

### 変更していないもの

`capexSustainedUtilizationThreshold`（0.92）・shortfall gate・inventory gate・
ongoing project gate・借入余力ゲート（`borrowingPressure < 1`）は**すべて維持**。
中断案件の再開判断も、残額を観測できないため従来の
「目標バッファ × capexCashSafetyMultiple」を維持しています。

`capexCashGateMode` で旧方式（`legacyMultiple`）も選べる形で残し、比較可能にしました。

## 3. `domesticPurchaseCashAllocationRatio` の 0.6 / 0.8 / 1.0 比較

**本番の既定値は 0.6 のままです。** 比較スクリプトは実行中だけ値を差し替え、
必ず元へ戻します（エンジンに注入口が無いための措置で、ゲームロジックは変更していません）。

| ratio | 資金ゲートbinding | 延滞イベント |
|---|---|---|
| 0.6 | 18 / 40 | **0** |
| 0.8 | 16 / 40 | **0** |
| 1.0 | **11 / 40** | **0** |

### 会社別

| 会社 | 指標 | 0.6 | 0.8 | 1.0 |
|---|---|---|---|---|
| BAL | raw不足 | 6,023 | 2,940 | **1,245** |
| | 営業利益 | 89.4M | 84.3M | **92.6M** |
| | 期末現金 / debt | 48M / 37M | 48M / 18M | 45M / 21M |
| **MASS** | raw不足 | 75,351 | 46,909 | **42,430** |
| | **営業利益** | **-26.2M** | **+19.3M** | **+17.6M** |
| | 信用区分 | **D** | **B** | **B** |
| | 期末現金 / debt | 2M / 35M | 18M / 44M | 22M / 46M |
| JPQ | raw不足 | 16,341 | 10,063 | **5,232** |
| | 営業利益 | 80.1M | 71.5M | 79.0M |
| VAP | raw不足 | 28,222 | 14,178 | **9,143** |
| | 営業利益 | 71.6M | 62.0M | **55.1M** |
| CONSV | raw不足 | 1,385 | 1,385 | 1,385 |
| | 営業利益 | 77.3M | 77.5M | 77.5M |

### 提案

**`domesticPurchaseCashAllocationRatio` を 1.0 にする（実質的に廃止する）ことを提案します。**

根拠:

1. **資金繰りは破綻しません。** 1.0 でも延滞イベント0件、全社の期末現金はプラス
   （22〜45M）、debt は 15〜46M で 0.6 のときと同水準です。
2. **MASSが赤字から黒字へ転じます**（-26.2M → +17.6M）。信用区分も D → B へ回復。
   0.6 の下では MASS は原料を買えず、生産できず、赤字が続き、担保が縮み、
   さらに借りられなくなるという悪循環に入っていました。
3. **原料不足が全社で大きく減ります**（BAL -79%、JPQ -68%、VAP -68%、MASS -44%）。
4. **二重制約が解消されます。** 今回の運転資金評価は資金需要側で既に
   給与・当期決済買掛・元利返済・最低現金バッファを差し引いており、
   0.6 の留保（「残りは賃金等の最優先支払に確保」）と目的が重複しています。
   0.6 という水準の根拠はコード・ドキュメントのいずれにも記録がありません。

### 唯一の懸念

**VAP の営業利益が 71.6M → 55.1M と下がります**（-23%）。
原料が買えるようになった結果、VAPが低採算の生産まで行っている可能性があります。
0.8 でも 62.0M と下がるため、この傾向は ratio を上げるほど強まります。

これは「資金制約が意図せず採算規律の代わりになっていた」ことを示唆します。
本来は採算判断で止めるべきものを資金不足で止めていた、ということです。
**1.0 へ変更する場合は、VAP の商品別採算判断を別途確認することを推奨します。**

**変更はまだ行っていません。ご判断ください。**
