## 1. 実装（既決定どおり）

### Single Source of Truth

`app/lib/v2/production/concentration.ts`

```ts
concentrationFactor(product, quantityTons): number
```

| 商品 | カーブ |
|---|---|
| HOSO | 8,000t以下 = 1.00 / 16,000t = 0.80 / 24,000t = 0.60 |
| PD・VAP | 4,000t以下 = 1.00 / 12,000t = 0.80 |

線形補間・**下限なし**。基準点を超えたあとの傾きは一定（8,000tごとに0.20低下）で、
上限数量を超えてもそのまま外挿します。

### 数量 → 必要Worker（直接計算）

`effectiveEfficiencyPerHeadTons` の係数決定部で

```
係数 = (省人化投資の上書き ?? labor intensity) × concentrationFactor(product, 数量)
```

と**乗算合成**しました。置換ではないため、PD省人化投資と集中効果は両立します
（打ち消し合いません）。

### Worker → 最大生産量（二分探索で逆算）

`maxQuantityForAvailableWorkers()`。代表生産量は**どこにも置いていません**。

```
requiredWorker(quantity) <= availableWorker を満たす最大の quantity
```

`calculateLaborCapacityFromAssignedHeadcount` もこの逆算へ置き換えました。
設備能力を探索上限にすることで「人を増やしても設備能力は超えない」性質は保たれます。

**集中効果が働かない数量域（HOSO 8,000t以下 / PD・VAP 4,000t以下）では、
まず閉じた式で解いて厳密解を返します。** 二分探索の丸め誤差を持ち込まないためで、
係数導入前との一致を検証する既存の回帰テストが厳密に通ります。

## 2. **判断が必要な事項 (1): 「下限なし」の数学的帰結**

必要Worker総数は

```
required ∝ quantity × concentrationFactor(quantity)
         = q × (1 + b·d/s) − q²·d/s        （上に凸の二次関数）
```

となり、**ある数量を超えると「たくさん作るほど必要人数が減る」という逆転が起きます。**

```
頂点 q* = (1 + b·d/s) · s / (2d)

HOSO   : q* = 24,000t
PD/VAP : q* = 22,000t
```

**HOSOの頂点 24,000t は `MAX_HOSO_CAPACITY_TONS` と完全に一致するため、
ゲーム内では到達しません。** PD/VAPの22,000tも、現行の商品別能力（4,000〜8,000t）と
増設単位（+350t / +250t）から見て遠い水準です。

したがって**現時点では実害はありません**が、これは「下限なし」というご指示の
数学的な帰結であり、実装上の不具合ではないことを明示しておきます。
逆算側は単調性が破れる領域へ入らないよう、探索上限を頂点で打ち切っています。

**HOSOの上限を24,000tより上へ広げる場合は、この逆転が実際に起きます。**
その時点で下限（floor）の要否を再検討する必要があります。

## 3. **判断が必要な事項 (2): SAI-5因果(1b) が閾値を下回る**

`SAI-5因果(1b): 営業基盤の高い会社ほど、同じ市場×商品での成約シェアが高い`

このテストは `concentrateOn("vap", 3)`（VAPへ集中させるシナリオ）＋営業不足ケースで、
「営業基盤の差が成約シェアの差を生む」という因果を検証しています。

| | 基盤最上位が最下位以上のシェアを取った割合 |
|---|---|
| 集中効果なし | **合格（60%以上）** |
| 集中効果あり | **56%（39/70）** |

※ もともと最終四半期の1断面（8セル）だけで判定しており、1セルの入れ替わりで12%動く
不安定な指標でした。**全四半期を集計して標本を70セルへ増やしたうえで56%**です。
しきい値（60%）は変えていません。集中効果を無効にすると同じ集計でも合格するため、
**小標本のノイズではなく、集中効果による実際の変化です。**

### 何が起きているか

集中効果は供給側の効果です。VAPへ集中した会社は必要Workerが減るため、
営業基盤が弱くても供給余力で成約を取れるようになります。
その結果「営業基盤 → 成約シェア」という因果が弱まります。

### 選択肢

- **(3-1)** これを正しいゲーム挙動として受け入れ、テストが守る因果を
  「営業基盤は成約シェアに効くが、供給側の優位に上書きされうる」へ改める
- **(3-2)** 集中効果のカーブを緩める（VAPの傾きを下げる等）
- **(3-3)** このテストを集中効果が働かない条件（専用fixture）へ分離する。
  ただし現在の実装では集中カーブがモジュール定数であり、エンジンへ注入する口が
  無いため、`ProductionParameters` へ移してエンジン全体へ通す改修が要ります

**期待値を機械的に下げることはしていません。ご判断をお願いします。**

capex提案は前後で完全に同一（BAL T3 HOSO / JPQ T5 PD / VAP T8 3件）。

### **集中効果は本番ベンチマークではほぼ効いていません**

理由: 原料制約（`domesticPurchaseCashAllocationRatio = 0.6`）により、
各社の商品別生産量が集中効果の基準数量（HOSO 8,000t / PD・VAP 4,000t）に
ほとんど届いていないためです。

営業利益の改善は +0.1〜+1.2M にとどまります。

### HOSO 12k→16k→20k→24k の経路（重点確認事項）

**成立していません。8Qでは BAL の 8,000t → 12,000t の1段のみです。**
Stage E の導入によっても変わりませんでした。

律速は集中効果ではなく原料です。前回報告した
`domesticPurchaseCashAllocationRatio` を 1.0 にする案を採ると原料不足が
BAL −79% / JPQ −68% / VAP −68% / MASS −44% まで減るため、
**そこで初めて生産量が集中効果の基準数量へ届き、HOSO増設の連鎖が回り始める**
と見込まれます。
