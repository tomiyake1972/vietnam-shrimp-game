PD/VAP と合わせて 30,000 を超えられないため意味が薄い）。
明示的な上限が必要なら別途ご指示ください。

## 2. 商品集中効率係数

### 2.1 定義（判断1反映：計画生産量ベース）

```
concentrationFactor(product, plannedProductionTons)
  = piecewiseLinear(plannedProductionTons, breakpoints[product])
```

| 商品 | 下限量 | 下限係数 | 上限量 | 上限係数 |
|---|---|---|---|---|
| HOSO | 8,000 | 1.00 | 24,000 | **0.60** |
| PD | 4,000 | 1.00 | 12,000 | **0.80** |
| VAP | 4,000 | 1.00 | 12,000 | **0.80** |

下限量以下は 1.00 固定、上限量以上は上限係数で固定。間は線形補間。

**検証値（指示N1〜N7）**:

| 生産量 | HOSO | PD | VAP |
|---|---|---|---|
| 4,000 | 1.00 | 1.00 | 1.00 |
| 8,000 | **1.00** | 0.90 | 0.90 |
| 12,000 | 0.90 | **0.80** | **0.80** |
| 16,000 | **0.80** | 0.80 | 0.80 |
| 20,000 | 0.70 | 0.80 | 0.80 |
| 24,000 | **0.60** | 0.80 | 0.80 |

**連続性（指示F4・テスト20）**: 8,000.001t で 0.99999… となり段差が無いことを
テストで固定する。8,000t ちょうどは 1.00。

### 2.2 既存 labor intensity との合成

```
effectiveCoefficient = (coefficientOverride ?? laborIntensityCoefficient[product])
                       × concentrationFactor(product, plannedTons)

requiredWorkers ∝ effectiveCoefficient
```

既存の `laborIntensityCoefficient = {hoso: 1.0, pd: 1.2, vap: 3.0}` は**削除しない**。
Excel専用ロジックも作らない（指示F4）。

## 3. **下限案の比較（追加判断への回答）**

### 3.1 前提の訂正 — PD省人化は「0.8の係数」ではありません

実装を確認したところ、PD省人化投資は factor を返すのではなく、
**PD係数そのものを 1.2 → 1.0 へ引き下げる**（`floorCoefficient = hoso係数 = 1.0`）。
最大削減率は 20% ではなく **16.67%（= 1 − 1.0/1.2）** です。

したがって実際の重畳は 0.8 × 0.8 = 0.64 ではありません。

| PD の状態 | effectiveCoefficient | base(1.2)比 |
|---|---|---|
| 何もなし | 1.2 | 1.000 |
| 省人化のみ（フル） | 1.0 | 0.833 |
| 集中のみ（12,000t） | 1.2 × 0.80 = 0.96 | 0.800 |
| **両方** | 1.0 × 0.80 = **0.80** | **0.667** |

**重畳後でも 0.667 であり、0.64 までは下がりません。**

### 3.2 重要 — 単純な下限は HOSO 設計を壊します

「最終 labor factor に 0.70 / 0.75 の下限」を**そのまま**適用すると:

| 商品 | 下限なし | 下限0.70 | 下限0.75 |
|---|---|---|---|
| HOSO 24,000t | **0.60** | **0.70 ← 設計が消える** | **0.75 ← 設計が消える** |
| PD 省人化＋集中 | 0.667 | 0.70 | 0.75 |
| VAP 12,000t | 0.80 | 0.80 | 0.80 |

指示F1は「HOSO 24,000t で 0.60」を明示しており、
**HOSOは集中効果ひとつしか効いていない**（省人化投資はPD専用でHOSO/VAPに影響しない）。
そこへ 0.70 の下限を掛けると、今回の設計の中心が失われます。

### 3.3 したがって下限は「重畳時のみ」に限定すべきです

推奨する定義:

> 下限は、**2つ以上の異なる効率化機構が同時に効いている場合にのみ**適用する。
> 単一機構（集中効果のみ）の場合は適用しない。

この定義なら:

| 商品 | 下限なし | 下限0.70(重畳時のみ) | 下限0.75(重畳時のみ) |
|---|---|---|---|
| HOSO 24,000t（集中のみ） | 0.60 | **0.60**（維持） | **0.60**（維持） |
| VAP 12,000t（集中のみ） | 0.80 | 0.80 | 0.80 |
| PD 集中のみ | 0.80 | 0.80 | 0.80 |
| PD 省人化のみ | 0.833 | 0.833 | 0.833 |
| **PD 省人化＋集中** | **0.667** | **0.70** | **0.75** |

**影響を受けるのは PD 省人化投資済みかつ PD 大量生産という1ケースのみ**です。

### 3.4 3案の評価

| 案 | 影響 | 評価 |
|---|---|---|
| **下限なし** | PD重畳で 0.667 | PD省人化投資の価値が最も高い。PD集中戦略がHOSOに対抗しうる。指示Lの「PD/VAPにもメリット」に沿う |
| **0.70（重畳時のみ）** | PD重畳が 0.667→0.70（効果 −5%） | 重畳の逓減を表現。影響は小さい |
| **0.75（重畳時のみ）** | PD重畳が 0.667→0.75（効果 −12%） | PD省人化＋集中の妙味がかなり削がれる |

**当方の推奨は「下限なし」**です。理由:

1. 実測上 0.667 であり、当初懸念の 0.64 より穏当。
2. PD 0.667 に対し HOSO は 0.60 まで下がる。**下限を入れるとPDだけが不利になり、
   HOSO一択リスク（指示L）を悪化させる**方向に働きます。
3. 「重畳時のみ」という条件付き下限はルールとして複雑で、
   プレイヤーへの説明が難しくなります。

ただし Phase 5 のベンチマークで PD 集中が強すぎると判明した場合、
0.70 を後から入れられるよう **パラメータとして実装**し、既定値を「下限なし」にします。

**ご確認いただきたい点**: 「下限なし」で進めてよいか、
それとも 0.70（重畳時のみ）を初期値にするか。

## 6. 段階的ベンチマーク計画（指示Rの推奨に対応）

各段階で同一 scenario / seed（`baseline` / `canonical` /
`test16-balance-YYYYMMDD`）で 5社×8Q を実行し、JSON/CSV を artifacts へ保存する。

| 段階 | 変更内容 | 目的 |
|---|---|---|
| **A** | 現行（`71cc788`） | baseline |
| **B** | + 初期営業60人のみ | 営業不足解消の効果を単独で測る |
| **C** | + common/freezing 30,000・PD/VAP能力・養殖4,000 | 能力再編の効果。原料制約の出方を見る |
| **D** | + HOSO capex 8M/+4,000t | 投資誘発の変化。HOSO偏重の兆候 |
| **E** | + 商品集中効果 | labor削減効果。HOSO一択リスクの本番 |
| **F** | 全変更（= E と同じ） | 最終確認 |

**注**: C〜E は積み上げなので F は E と同一になる。
指示の A〜F をそのまま採用しつつ、F は「全変更の最終確認」と位置づける。

各段階で追跡する指標（指示M）:

```
営業: sales headcount / hires / market allocation / contracts
生産: HOSO/PD/VAP production / common・product・freezing 稼働率
労務: required worker / actual worker / concentration factor / labor saving / overtime・temp
原料: farm supply / domestic / import / raw inventory / raw shortage
在庫: finished goods / backlog
財務: revenue / gross profit / contribution margin / operating profit / net profit /
      cash / debt / working capital / capex / depreciation / sales payroll / labor cost
```

現行の `marketAwareSalesBenchmark.ts` を拡張して生産・労務・原料の項目を追加する
（新スクリプトを作らず、既存の決定論的な収集経路をそのまま使う）。

**取得できない項目があれば「現行diagnosticsでは取得不可」と明記し、推定で埋めない。**

## 7. golden test の扱い（指示O）

営業60人で壊れるテストを2分類し、**期待値の機械的書き換えはしない**。

| 分類 | 対応 |
|---|---|
| **A: 初期ゲーム状態の検証** | 新しい初期値へ期待値を更新（何を検証しているかは変わらない） |

B に該当することが判明しているもの:
- `Test14 Turn1型ゴールデンケース: 営業が強い制約と診断される`

これらは営業60人では前提が成立しないため、
fixture override（営業14人など）を明示的に渡す形へ変更する。
**初期値変更によって診断ロジックのテスト意味が消えないようにする。**

## 9. リスクと未確定事項

1. **集中係数の適用箇所が2つある可能性**。
   `calculateLaborCapacityFromAssignedHeadcount`（N人→何t作れるか）と
   `requiredHeadcountForQuantity`（Xt→何人必要か）の両方が
   `effectiveEfficiencyPerHeadTons` を通る。計画生産量ベースなら両方に同じ係数が入り
   整合するが、**実装時に「計画生産量」をどこから渡すか**の配線が必要。
   意思決定 → 労務配分の経路に計画量を通す改修が要る。想定より広くなる可能性がある。

2. **MASS の common 36,000 → 30,000 は能力削減**。
   MASS は現在 HOSO 30,000 を持ち common 36,000 で運用している。
   HOSO 12,000 / common 30,000 は大幅な縮小であり、
   MASS の既存戦略・Standard AI の投資判断が変わる。段階Cで実測する。

3. **養殖 4,000 で原料が回るか未検証**。
   段階Cで raw shortage が急増する可能性がある。実測後に報告する。

4. **HOSO 24,000 + PD + VAP が common 30,000 に当たる**設計のため、
   HOSO を上げるほど PD/VAP を削らざるを得ない。
   これは意図どおりだが、Standard AI がこのトレードオフを扱えるかは未検証。
