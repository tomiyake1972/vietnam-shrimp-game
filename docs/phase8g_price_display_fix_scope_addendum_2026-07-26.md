# Phase 8G 中間報告①addendum：価格表示修正の範囲確定と±8/12%クランプの扱い

コード変更は伴わない（`fix/v2-8g-sales-allocation-and-price-display`ブランチ、

## 1. 今回の価格対応の性質の確定

コミット`95a6c15`（`app/v2/company-lab/marketPriceViewModel.ts`）による修正は、
**価格形成ロジック（`hosoPricing.ts`・`consumerInventory.ts`・`marketAdapter.ts`等の
実際の価格計算エンジン）を一切変更していない**。

修正範囲は、Company Labの表示専用コード（`buildDestinationMarketPriceRows()`）に
限定される。具体的には、真正な前期確定`MarketQuarterResult`が存在しない初回四半期に、
「ベトナムHOSO価格 × 市場係数」という代理値を、あたかも真正な前期実績であるかのように
前期比計算・表示に使っていた問題を修正し、真正な前期確定価格が無い場合は
HOSO/PD/VAPすべてで「前期比：―」（`unavailable`）と表示するようにした。

これにより、「真正な前期確定価格が存在しない初回四半期に、代理値を前期実績として
表示していた問題」の修正として、今回の対応を確定する。価格計算エンジンの計算結果
そのもの（当期確定価格）は変更前後で同一であり、変わったのは前期比の表示判定のみ。

## 2. ±8%（通常時）／±12%（大規模ショック時）の変動上限について

### 現状の技術的制約

- 現在の価格計算層（`MarketQuarterInput`および`hosoPricing.ts`の`clearHosoMarket()`の
  入力）には、「これは大規模ショックである」というシナリオ／イベント種別の情報が
  一切届いていない。
- シナリオイベントは需給の基礎変数（供給量・需要量等）のみを動かし、価格へ直接
  触れないという既存設計原則がある。ショック種別に応じて変動上限を切り替える仕組みを
  新設すると、この原則と衝突する新しい設計判断（どの情報をもって「ショック」と
  判定するか、その判定をどの層に持たせるか）が必要になる。
- 加えて、既存の仕様文書には、変動幅について複数の異なる記述が併存しており、
  「通常時±8%／大規模ショック時±12%」を一意に確定させるには、既存仕様間の
  矛盾を解消する設計判断が別途必要になる。

### 決定（三宅さん、2026-07-26）

- **Phase 8Gでは実装しない。** 上記2点（ショック種別シグナルの不在、既存仕様間の
  変動幅記述の不一致）は、Phase 8Gの停止条件（指示§10：既存の消費国在庫定義が
  相互に矛盾し設計判断が必要な場合、に準ずる設計課題）に該当するものとして、
  実装せず設計課題として本ドキュメントに記録する。
- **現在の±20%クランプ（`hosoPricing.ts`の`maxQuarterlyPriceChangeRatio: 0.2`、
  Phase 6.3・コミット`f589a7b`で導入済み）は、今回のこの判断のみを根拠に
  削除・変更しない。** 変動幅の再設計を行う場合は、別途あらためて設計判断を
  仰いだ上で着手する。
- Section 8で予定されていた必須テストのうち、±8%/±12%の2段階クランプの挙動を
  検証するもの（例：「大規模ショック時にのみ±12%まで許容され、通常時は±8%に
  収まる」といった項目）は、**今回の受入対象から除外する。** 今回コミットした
  回帰テスト（`marketPriceViewModel.test.ts`の§B-1・§B-2）は、あくまで
  「代理値を使わない」「全市場が同一のchangeRatioにecho しない」ことのみを
  検証しており、変動幅クランプの段階分けそのものは検証対象にしていない。

### 将来再検討する場合の前提条件（メモ）

再検討する場合は、少なくとも次の設計判断が必要になる：
1. 「これは大規模ショックである」という信号をどの層（シナリオ定義／
   `MarketQuarterInput`／別の専用フィールド）にどう持たせるか。
2. その信号を、既存の「イベントは基礎変数のみを動かす」原則とどう両立させるか
   （価格へ直接触れる例外を認めるのか、基礎変数側の変動幅を介して間接的に
   ±12%相当を実現するのか）。
3. 既存仕様文書内の変動幅記述の不一致をどちらに統一するか。
