# ShrimpX V2 引き継ぎ／完了報告の出力形式

ShrimpX V2 のユーザーは、報告内容を ChatGPT 側（#04 / #05）へそのまま貼り付けて
共有している。したがって報告は **1つの連続したコードブロック** でなければならない。

## 絶対規則

1. **報告全体を1つの ``` フェンスで囲む。** 複数ブロックに分けない。
   フェンスの外に説明文・前置き・後書きを置かない（ブロックだけを出力する）。
2. **Markdown 表を使わない。** 貼り付け先でレンダリングされないため、
   桁を空白で揃えたプレーンテキストの表にする。
3. **Markdown 見出し（#）・太字（**）を本文に使わない。** 代わりに
   `■` `★` `═` `───` などの記号と全角スペースで構造を作る。
4. **省略しない。** 「詳細は上記参照」で逃げず、その1ブロックだけを読めば
   完結するように数値と根拠をすべて含める。
5. 指示側が報告項目を番号付きで列挙している場合、**その番号と順序をそのまま使う**。
   未実施の項目も番号を飛ばさず「未実施（理由）」と明記する。

## 標準の構造

```
【ShrimpX V2 — <Phase名> 完了報告（コピペ用）】

═══════════════════════════════════════════════
■ 最初にお伝えする点（あれば）
═══════════════════════════════════════════════
指示の前提が崩れている・方針変更が必要・受入不可の発見がある場合はここへ最初に置く。
後ろに埋めない。

═══════════════════════════════════════════════
1. <指示の報告項目1>
═══════════════════════════════════════════════
...

（指示の項目数だけ繰り返す）

═══════════════════════════════════════════════
N. 未解決事項
═══════════════════════════════════════════════
(1) ...
(2) ...

═══════════════════════════════════════════════
今回のコミット
═══════════════════════════════════════════════
<hash>  <件名>
...
診断スクリプト実行例：
  npx tsx scripts/xxx.ts
```

## 数値表の書き方（Markdown 表の代わり）

```
  会社     DS2       DS3      変化     目標               到達
  MASS   28,583   43,889    +54%   90,000–100,000     0/5
  BAL    26,359   25,889     -2%   55,000– 65,000     0/5
```
- 見出し行と data 行の桁を空白で合わせる
- 数値は3桁区切り、単位は列見出しか値に付ける
- 強調は `★` を行頭に置く

## 必ず含める項目

- branch / HEAD（コミット済み・push 済みかを明示）
- 検証結果（npm test の pass/fail 実数、tsc、eslint の errors/warnings、build）
  - build が環境要因で失敗する場合は「変更前 HEAD でも再現する」ことまで書く
- Preview deploy が不可能な環境では `Preview deploy required externally` と明記し、
  **URL を推測して書かない**
- 測定値は実測のみ。推定値を実測のように書かない
- 指示と実測が食い違った場合は、食い違いを最初のセクションで明示する

## やってはいけないこと

- ブロックを分割する
- Markdown 表・見出し・太字を使う
- 「詳細は前述のとおり」で数値を省く
- 未実施項目を黙って落とす
- Preview URL を推測で書く
